## How an edit operation is read

Premiere's editing features are mostly **operations**: a tool that changes several clips at
once. Montagent's agent edits the project's literals itself. The write-tool invariant
([ADR-0011](../../adr/0011-tool-surface-reads-checks-renders.md)) forbids an
`update_element` tool, and `shift` is the one edit Montagent does arithmetic for
([ADR-0005](../../adr/0005-absolute-integer-milliseconds.md)). So this table reads an
operation by mechanism as follows:

- **have** means the result is writable as literals and `validate` checks it. No tool is
  needed for that. Example: a slip changes `source_start` and `source_end` by the same amount.
- **partial** means part of the mechanism is missing. Usually Montagent promises the
  arithmetic but has not built it. Example: `shift` refuses a negative `delta`, so time cannot
  be closed up.
- Pure GUI chrome, such as track height or the Selection Follows Playhead button, is listed. Its
  nearest Montagent mechanism is the `query` cut list or the `frame` contact sheet.

## Notable gaps

1. **`shift` refuses a negative `delta`.** Extract, ripple delete, close gap, shortening ripple
   trims, asymmetrical trims and ripple speed changes are all partial for this one reason.
   ADR-0012 already specifies the mechanism, and `shift.rs` defers it to a follow-up. It is the
   biggest lever in this chapter. The full rearrange page shows that Premiere shifts only the
   destination track, so rearrange no longer depends on it.
2. **No markers of any kind.** Sequence, clip, spanned, chapter, segmentation, web-link, Flash
   cue-point and Effect Controls markers are all missing. So are Ripple Sequence Markers,
   snap-to-marker, hold-on-marker and marker-based sync. Chapter metadata in the delivered MP4
   depends on them (#892).
3. **No multicam.** There is no synced angle set and no sync by audio, timecode or marker.
   `probe` reads no source timecode (LTC, sound or aux), so timecode sync has nothing to
   work from.
4. **Integer `fps` and progressive square pixels only.** NTSC rates (23.976, 29.97, 59.94)
   cannot be written as a project rate. There is no interlaced output, no field-order
   interpretation or deinterlace for interlaced sources, and no non-square output PAR. No
   override fixes a file's PAR: ADR-0023's declared `par` is not in the v0.2.0 schema.
5. **Sequence-level processing settings are missing.** Editing Mode, preview codec and size,
   Maximum Bit Depth, working colour space and tone mapping, and linear-light compositing have
   no equivalent. Most belong to #886 and #894.
6. **Nesting is refused while it carries a clock.** The space-only `nest` (#632) is
   provisional and not in v0.2.0. Subclips, Edit Subclip and Convert to Master Clip are refused
   as an asset table (ADR-0002); the per-element source range gives the same edit result.
7. **Track-level switches are missing:** track lock, track mute/solo/output toggle, element
   enable/disable, and sync lock on a chosen subset of tracks.
8. **Speed interpolation is frame sampling only.** There is no frame blending or optical
   flow, and reversed or ramped audio is refused (ADR-0157).
9. **Adjustment layers are partial.** A blend-mode `rect` tints the backdrop, but no effect can
   filter what lies below an element. No ADR refuses it, so it is open.
10. **Linking separate sound to picture.** A `video`'s own sound always moves with it, but
    double-system audio has no link, merge or per-pair sync check. A video's embedded sound
    cannot be split off for a J or L cut; a second `audio` element is needed.
11. **Quality-control listings.** The Sequence Index's flash-frame filter and CSV export, and
    duplicate-frame markers, have no finding or output in Montagent.
