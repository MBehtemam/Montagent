# Premiere Pro gap: collaboration, and Premiere with other apps

Research ticket [#911](https://github.com/MBehtemam/Montagent/issues/911), on the map
[#882](https://github.com/MBehtemam/Montagent/issues/882). Area slug: `workflow-collab`. This file
sits beside [`workflow.md`](https://github.com/MBehtemam/Montagent/blob/research/premiere-gap-workflow/docs/research/premiere-gap/workflow.md)
(branch `research/premiere-gap-workflow`, [#894](https://github.com/MBehtemam/Montagent/issues/894)).
It takes over that file's *Collaboration* rows and its third-party plug-in rows, now sourced from the
full Adobe pages, and adds the two chapters that file did not walk.

- **Date:** 2026-10-10
- **Premiere side:** the census pages ([#883](https://github.com/MBehtemam/Montagent/issues/883),
  Premiere 26.5) assigned to `workflow-collab`: 88 pages from two chapters of
  `helpx.adobe.com/premiere/desktop/`, *Collaborate with others* (Creative Cloud Libraries,
  Productions, Team Projects, Frame.io) and *Use Premiere with other apps* (plug-ins and
  extensions, After Effects, Audition, Photoshop). Also the three What's-new pages (*What's new*,
  *Release notes*, *beta features*). **Every page was fetched and read in full, so every row's
  source is (F).** No row rests on a search snippet, a recalled URL or the agent's own knowledge.
- **Montagent side:** tag `v0.2.0` (`51aa4b5`, = `origin/main` on this date). Read: `CONTEXT.md`,
  `README.md`, `schema/montagent.schema.json`, `docs/adr/` (ADRs cited per row),
  `crates/montagent/src/mcp.rs` (the ten MCP tools), `crates/montagent/Cargo.toml`, and `skills/`.
  Sibling area files were read so as not to contradict them: `workflow.md`, `import.md`,
  `editing.md`, `titles.md`, `export.md`.
- **Status vocabulary:** as the map uses it: `have`, `have (skill)`, `partial`, `missing`,
  `refused`. A `refused` row cites the ADR (or the ADR-0145 invariant) that refuses it. A `partial`
  row says what is missing. *GUI-only* marks a mechanism that only serves a panel or a mouse; no ADR
  refuses a GUI, so those rows are `missing`.
- **Git counts as Montagent's mechanism** where git itself does the job, as `workflow.md` already
  reads it (its *Project versions* and *Undo* rows are `have` through git). The project is one JSON
  file that the README says to check into git, diff and review, and ADR-0159 §1 keeps that authority
  with the agent. A job only a git *host* does (accounts, invitations, archiving a repository) is
  outside Montagent, so it is `missing`.

**Counts (87 rows):** have 14 · have (skill) 0 · partial 25 · missing 36 · refused 12

**Corrections to earlier area files.**

- `workflow.md` rows marked † (Team Projects, Frame.io, Productions, Creative Cloud Libraries,
  third-party video and audio plug-ins, importer/exporter plug-ins, ExtendScript) are re-sourced
  here to their (F) pages. Their mechanisms hold. The full pages split each into several
  mechanisms, which are separate rows below. No status changes.
- Two mechanisms are corrected. Productions *"cross-project referencing"* refers to a **master
  clip** in another project, not a sequence. The media half is `have` (two projects name one file),
  and the master-clip half is ADR-0002's refused catalogue (P9, P10). Productions *"project
  locking"* has three states. A read-only project can still be viewed, exported and copied from
  (P4, P5).
- `import.md` lists *"Import After Effects compositions (Dynamic Link)"* as `missing`. The full
  pages show the link makes After Effects render the composition each time Premiere asks for a
  frame. That is a path naming a program to run, which ADR-0145's closed-vocabulary test rules out,
  so it is `refused` here (A3–A6). The route that is open, rendering the composition and placing the
  file, is `have` (A8).
- **Illustrator:** neither chapter has an Illustrator page. Illustrator import is `import.md`'s
  row (`refused`, ADR-0027/0171).

## Notable gaps

- **Nothing coordinates editors before they collide.** Premiere has project locking (P4), sequence
  locking (T5), presence (T4), change notices (P6, T7) and publish-and-update (T6). Montagent has git:
  publish, update, history and forks are all `have` (T6, T12, T13), but two editors meet only at the
  merge. There is no lock and no presence, and there is no JSON-aware merge driver, so a merged file
  is checked by `validate` only after the fact (T9).
- **No reference from one project into another.** Productions' master-clip referencing (P9),
  source-clip effects (P10), shared markers (P14), Project Shortcuts and Linked Team Projects (P17)
  all assume one project can point into another. Sharing a media *file* between projects is `have`.
  Pointing at a *clip* in another project is ADR-0002's refused catalogue (P9, P10), and a project
  reference is open (ADR-0166 does not refuse a shared space).
- **Paths don't survive a move.** A relative `source` resolves against its own project's folder
  (ADR-0053). So copying an element between projects in different folders (P13), or moving a project
  inside a production (P2), breaks its paths, and nothing rewrites them. An absolute path is never
  translated between platforms (P19). `validate` catches every case as `E-SOURCE-MISSING`, but the
  repair is by hand. Team Projects' per-machine media mapping (T15) is refused under ADR-0053.
- **No review loop on the picture.** Frame.io's share link (F3), frame-accurate comments with
  drawings (F6), comments imported as markers (F7) and markers exported as comments (F8) are all
  missing. Montagent renders the file (`render`), but it has no upload or link, and no markers to
  carry comments. ADR-0017 already says where a comment would live: a sidecar file in the repo,
  never the project.
- **No shared settings across projects** (P3, P8): no production-wide renderer, colour or scratch
  disks, and no shared preview files. Montagent has no renderer choice or preview cache to share,
  and its single CPU renderer makes the fallback question moot (P7, `have`).
- **No round trip to other apps.** Copy and paste to and from After Effects (A1, A2), sending a
  sequence to Audition as a multitrack session (U2, U3), PSD import (S3) and a new Photoshop canvas
  (S1) are missing. What works is by file: edit a still or a WAV outside and the project picks it up
  (S2, U1 partial), bring back a rendered movie (S4), or render an After Effects composition and
  place it (A8).
- **Refused by ADR:** Dynamic Link's live compositions (A3–A7, ADR-0145 *closed vocabulary*:
  a path names media to decode, never a program to run), every plug-in kind except codecs (X1, X2,
  X3, X5: ADR-0003, ADR-0017, ADR-0145), LUT-based Looks (L6: ADR-0040, ADR-0049), source-clip
  effects (P10: ADR-0002) and local-only media mapping (T15: ADR-0053).
- **No library or stock service.** Creative Cloud Libraries (L1–L3) and Adobe Stock search and
  licensing (K1) are missing. The mechanisms they serve are mostly `have` by file: one asset file
  updated once reaches every project that names it (B2), and swapping a watermarked preview for the
  licensed file keeps every edit (K2).
- **Account and hosting features are outside Montagent:** invitations, archiving and project lists
  (T3, T16, T17, F9). They are `missing` because no part of Montagent does them, not because an ADR
  refuses them.
- **The remote instance is still unshipped.** Team Projects (T1) and editing on a cloud machine (B1)
  would lean on ADR-0159's HTTP door and named workspaces. That ADR is accepted, but v0.2.0 builds
  `rmcp` with `transport-io` only.
