## Three facts that decide most rows

1. **Video and audio decode through the user's own `ffmpeg`** (ADR-0009, floor ffmpeg 7.1 per
   ADR-0115, a missing one is `E-TOOL-MISSING` per ADR-0091), and every source is probed by
   `ffprobe` (ADR-0011). So a codec "is supported" exactly when the user's `ffmpeg` decodes it.
   The repository tests H.264 MP4, ProRes (incl. 4444) and VP9-alpha WebM
   (`docs/research/alpha-decode/`, ADR-0096); other ffmpeg codecs marked `have` below ship the
   mechanism but no repo test exercises them. Every decoded frame becomes **8-bit RGBA**
   (`decode.rs`: `-pix_fmt rgba`), with no colour management, tone mapping or deinterlacing.
2. **Stills decode through Skia** (`Raster::decode` → `Image::from_encoded`), pinned to the
   codecs in the prebuilt key: PNG, JPEG and GIF (wuffs) are named in `THIRD-PARTY.md`. WebP,
   HEIF, TIFF, TGA, DPX, PSD and EXR are not in the pin. A still Skia cannot decode is only
   caught at paint time as `E-NOT-PAINTED-UNDECODABLE` (ADR-0093), not by `validate`.
3. **There is no media catalogue and no per-source record.** `source` is written inline on each
   element and "asset" is not in the vocabulary; ADR-0002 refuses an asset table ("`source` never
   gets a table") and ADR-0053 refuses even an `assetRoot`. The schema is closed (ADR-0017), so
   nothing can hang a note, a marker, a timecode or a metadata field on a source or an element
   beyond `id`, `group` and a track's `name`. Every Premiere feature whose object is a
   Project-panel item (bins, subclips, offline clips, merged clips, metadata, search bins) has
   nothing to attach to; the ones that need a bin are refused, the rest are missing.

Two accepted ADRs in this area are **not in the v0.2.0 schema**: ADR-0023's `par` key and
ADR-0140's `swaps` (neither key appears in `schema/montagent.schema.json` or the element model).
ADR-0184 (`channels`, `pan`) is still `proposed`. ADR-0159's remote instance is accepted but
v0.2.0 binds the MCP stdio transport only (`mcp.rs`). Rows that lean on these say so.

## Changes in this pass

- **Mechanisms corrected (27 rows):** CineForm, AV1, ProRes RAW, Raw Source Settings, sample-rate
  conform, audio channel interpretation, multiple audio streams, a video file's audio, default
  media scaling, SVG, VFR, HDR sources, remove pulldown, alpha interpretation, colour override /
  input LUT, Import mode, ingest copy with checksum, create proxies, toggle proxies, Media Browser,
  remote media, relative-path relink, changed-on-disk detection, Project Manager, merge clips,
  stereoscopic VR and stereoscopic 3D. The notable ones:
  - *ProRes RAW*: the Supported-formats page now lists it as native (with ProRes HDR and log), and
    26.5 adds raw parameters on the timeline. The old row said it needed Apple's decoder.
  - *Default media scaling*: the preference offers **Scale to frame size / Fit to frame / None**.
    *Set to Frame Size* is a separate timeline command that keeps native resolution.
  - *Relink*: Premiere checks the current path plus two historical paths, then searches the
    project folder and its parent, matching across macOS and Windows. It does not simply resolve
    relative paths.
  - *Merge clips* syncs by In point, Out point, timecode or numbered clip marker, never by audio.
  - *Media Browser ingest* copies only the selected clips, keeps the card folder structure, and
    recommends *Copy With MD5 Verification*.
  - *HDR sources*: tone mapping of HLG/PQ and log footage into Rec. 709 is automatic and on by
    default.
  - *Create proxies*: the default is Half size ProRes Proxy, jobs run in Media Encoder, and files
    get a "_Proxy" suffix in a Proxies folder. *Toggle proxies* is the *Enable proxies* media
    preference, not a monitor button.
  - *Stereoscopic VR*: with no VR metadata, Premiere infers the layout from the frame shape
    (2:1 mono, 1:1 over/under, 4:1 side-by-side).
  - *Import mode* is the New Project dialog's Import desktop, with a selection tray, Organize Media
    (new bin), Copy media with MD5, Create new sequence from the first asset, and Automatic
    transcription.
  - *Interpret Footage* field order offers Use Field Order from File, or conform to No Fields,
    Upper or Lower; *Remove pulldown* appears on no Adobe page (only a third-party plug-in), so it
    is now unconfirmed.
  - *AV1* and *SVG* appear on no Adobe page, so both are now unconfirmed. *OpenEXR*, *HEIF*,
    *BMP/DIB/RLE*, *ICO*, *TGA* and *DPX* are confirmed.
  - *Project Manager*: Collect Files and Copy, or Consolidate and Transcode to MXF OP1a, DNxHD MXF
    or QuickTime, with handles from 0 to 999 frames.
- **Status changed (1):** *Relative-path relink when a project moves* (now *Automatic relink*)
  went `have` → `partial`. Montagent keeps relative paths but has no historical paths and no
  search.
- **Split, not changed:** *Colour space override / input LUT* is now two rows. The override stays
  `missing`; the per-clip input LUT is a new `refused` row (ADR-0040, ADR-0049), matching the
  colour file (#886). Every other corrected mechanism left its status as it was.

## Notable gaps

- **Camera raw is entirely missing**: R3D (incl. R3D NE), ARRIRAW (incl. HDE), ARRICORE, BRAW,
  ProRes RAW, Canon CRM, Sony RAW/X-OCN, Nikon N-RAW and CinemaDNG. ffmpeg (ADR-0009, ADR-0115)
  has no decoder for any of them, so the only route is transcoding outside Montagent.
- **Stills beyond PNG, JPEG and GIF**: TIFF, TGA, DPX, PSD, HEIF, WebP, EXR and legacy titles are
  missing from the Skia pin. Worse, `validate` passes them (ffprobe reads them) and only `render`
  refuses (`E-NOT-PAINTED-UNDECODABLE`), the kind of validate/render split ADR-0131 closed for
  remote sources.
- **Decode is 8-bit RGBA with no colour pipeline**: no HDR tone mapping, high-bit-depth, log or
  colour-space handling, no data-range or CICP reading, no deinterlace. Interlaced DV/HDV/XDCAM/IMX
  is drawn combed.
- **Interpret footage is mostly unshipped**: ADR-0023's `par` key is accepted but not in the v0.2.0
  schema, and `decode.rs` skips PAR (#274). The frame-rate override exists only as a per-element
  `speed`. The integer project `fps` cannot state 23.976 or 29.97.
- **No interchange import at all**: PRPROJ (beyond hand-copying JSON), FCP XML, AAF, EDL, OTIO,
  batch lists, PREL, CHPROJ, AEP and caption files (SRT, SCC, MCC, STL, DFXP).
- **Proxies mean something else**: Montagent's 720p/540p `preview` tiers (ADR-0046/0065/0186) cut
  paint cost but not decode cost. There are no proxy files to create, attach, reconnect, detach or
  watermark.
- **No ingest, card handling, Project Manager or Render and Replace**: no copy-and-verify (MD5),
  transcode-on-ingest, Media Browser card reading, spanned-clip joining, OP-Atom assembly, collect,
  consolidate-with-handles, or flattening back to a source.
- **No per-source record**: offline clips, metadata (XMP, schemas, clip data), markers of every
  kind, source timecode and the Search panel's filters all need a place to attach facts to a
  source, which the closed schema (ADR-0017) and the inline `source` (ADR-0002) do not give.
- **No recording**: no audio input, no voice-over, no mixer record.
- **Audio channels**: every input is downmixed to the 48 kHz stereo bus, silently. ADR-0184's
  `channels` routing is still `proposed`, and there is no stream selection or 5.1/ambisonics.
- **Relink is a manual string edit**: offline detection is strong (`E-SOURCE-MISSING`, the content
  guard of ADR-0092), but nothing searches for a moved file, keeps path history, or matches paths
  across macOS and Windows.
- **Refused by design**: the Project panel, bins and every bin operation, subclips, freeform view
  and duplicate consolidation (ADR-0002, no asset table); AI/EPS, SVG and Vector Motion (ADR-0027,
  ADR-0171; the SVG route is the prerender skill); Media Offline frames in a deliverable
  (ADR-0093); exporting from proxies (ADR-0186); input LUTs and AMIRA camera LUTs (ADR-0040,
  ADR-0049); timecode display formats, frame counts and the Timecode panel (ADR-0005).
- **Accepted but unshipped in v0.2.0**: ADR-0023 `par`, ADR-0140 `swaps`, and ADR-0159's remote
  instance (stdio only). A URL source is validated but never rendered (ADR-0131).
