# Premiere Pro gap: workflow, interface, monitors, performance, collaboration, extensibility, platforms

Research ticket [#894](https://github.com/MBehtemam/Montagent/issues/894), on the map
[#882](https://github.com/MBehtemam/Montagent/issues/882). Area slug: `workflow`.

- **Date:** 2026-10-10
- **Montagent side:** tag `v0.2.0` (`51aa4b5`, = `origin/main` on this date). Read: `CONTEXT.md`,
  `README.md`, `schema/montagent.schema.json`, `docs/adr/` (ADRs cited per row),
  `crates/montagent/src/mcp.rs`, `crates/montagent/src/cli.rs`, `crates/montagent/Cargo.toml`,
  and `skills/`.
- **Premiere side:** Adobe's own Premiere help pages (`helpx.adobe.com/premiere/desktop/…` and
  `helpx.adobe.com/premiere-pro/using/…`) and Adobe's UXP developer docs
  (`developer.adobe.com/premiere-pro/uxp/`). **Source caveat:** this session's egress policy
  refused direct fetches of `helpx.adobe.com` and `developer.adobe.com` (HTTP 403 at the proxy),
  so each mechanism below is taken from the content of those Adobe pages as returned by a web
  search restricted to `helpx.adobe.com`. Every URL in the table appeared in those results, except
  rows marked **†**. For a **†** row the session's shared web-search budget ran out before
  Adobe's page could be located. The mechanism is stated from Adobe's product as generally
  documented, and the URL given is the Premiere desktop help hub. Those rows need their exact page
  pinned before assembly (see *Source gaps*).
- **Status vocabulary:** as the map uses it. `have`, `have (skill)`, `partial`, `missing`,
  `refused`. A `refused` row cites the ADR that refuses it. A `partial` row says what is missing.
  Rows marked *GUI-only* describe a mechanism that exists to serve a hand on a mouse or an eye on
  a panel. No ADR refuses a GUI, so these rows are `missing`, not `refused`. ADR-0011 makes the
  agent's own editor the editing surface, and they are flagged so assembly can group them.

## Notable gaps

- **No GPU, anywhere.** No GPU rasterization (ADR-0021: deferred, not decided), no multi-GPU, and
  no hardware decode. Premiere has *removed* its software-only renderer (25.2), so on this point
  the two tools now sit at opposite ends. Hardware *encode* is the one GPU lever an ADR refuses
  (ADR-0143).
- **No preview-file cache.** There is no equivalent of the render bar, Render In to Out kept as
  preview files, or Use Previews at export. Every `render` paints every frame, and a partial
  render is a separate file nobody tracks.
- **No live monitor.** Looking is call-and-return: a still, a contact sheet, or a proxy MP4.
  There is no real-time scrub, no alpha or matte view, no two-up or split comparison image, and
  no way to view a raw source file without a project around it.
- **Collaboration is git, and only git.** There is no JSON-aware merge, no presence, no project
  locking, no cross-project reference (Productions), no review-and-comment loop on the *video*
  (Frame.io), and no shared asset library (CC Libraries). The remote instance (ADR-0159) is
  accepted but not in v0.2.0 (stdio-only transport).
- **No automatic safety net inside a session.** Auto Save and the History panel exist only at
  the granularity the agent commits.
- **Safe margins are craft, not tooling.** The numbers live in `montagent-craft`. Nothing draws
  them on a frame, and no `validate` check enforces them.
- **Refused by ADR:** third-party video and audio plug-ins (ADR-0003, ADR-0017, ADR-0145),
  hardware encoding (ADR-0143), and automatic updates (ADR-0064).
- **GUI-only rows (8):** workspaces, panels, keyboard shortcuts (both rows), appearance,
  multiple monitors, UXP panels, and control surfaces. These are `missing`, because no ADR
  refuses a GUI. Assembly may want to group them.
