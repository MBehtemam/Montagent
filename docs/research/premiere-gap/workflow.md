# Premiere Pro gap: workflow, interface, monitors, performance, collaboration, extensibility, platforms

Research ticket [#894](https://github.com/MBehtemam/Montagent/issues/894), re-sourced under
[#911](https://github.com/MBehtemam/Montagent/issues/911), on the map
[#882](https://github.com/MBehtemam/Montagent/issues/882). Area slug: `workflow`.

- **Date:** 2026-10-10
- **Montagent side:** tag `v0.2.0` (`51aa4b5`, = `origin/main` on this date). Read: `CONTEXT.md`,
  `README.md`, `schema/montagent.schema.json`, `docs/adr/` (ADRs cited per row),
  `crates/montagent/src/mcp.rs`, `crates/montagent/src/cli.rs`, `crates/montagent/Cargo.toml`,
  `crates/montagent-render/src/encode.rs` (the mix bus), and `skills/`.
- **Premiere side (re-sourced for #911):** every row now cites the Adobe page it comes from,
  marked **(F)**: the page was fetched and read in full. The pages are the census download
  (#883) of `helpx.adobe.com/premiere/desktop/` (Premiere 26.5): this area's 107 pages (Get
  started: project panel, download and install, keyboard shortcuts, preferences, accessibility,
  monitors, technical requirements, workspace tour, touch; and Render sequences for playback),
  the three What's-new pages, and, where an existing row's feature is documented elsewhere in
  the guide, that page (found by searching all 807 pages). The earlier source caveat no longer
  applies: no row rests on a search snippet, a recalled URL (the old **†** rows) or the
  agent's own knowledge. No row is unconfirmed. One mechanism, Adobe's UXP class names, came
  from `developer.adobe.com`, which no helpx page repeats, so it was dropped from the row.
- **Status vocabulary:** as the map uses it. `have`, `have (skill)`, `partial`, `missing`,
  `refused`. A `refused` row cites the ADR that refuses it. A `partial` row says what is missing.
  Rows marked *GUI-only* describe a mechanism that exists to serve a hand on a mouse or an eye on
  a panel. No ADR refuses a GUI, so these rows are `missing`, not `refused`. ADR-0011 makes the
  agent's own editor the editing surface, and they are flagged so assembly can group them.
- **Defaults:** a Premiere preference that sets a *default* applied when an item is created or
  imported is `missing`: Montagent never creates or imports on its own, so it keeps no defaults,
  and every value is written on the element (ADR-0011, ADR-0145 *literal values*). The row names
  the field that carries the value.
- **Collaboration:** the collaboration rows below (Team Projects, Frame.io, Productions,
  Creative Cloud Libraries, and the Collaboration preferences) are kept and re-sourced but not
  extended. The full collaboration and other-apps inventory is in
  [`workflow-collab.md`](./workflow-collab.md).

## Notable gaps

- **No GPU, anywhere.** No GPU rasterization (ADR-0021: deferred, not decided), no multi-GPU, and
  no hardware decode. Premiere has *removed* its software-only renderer (25.2), so on this point
  the two tools now sit at opposite ends. Hardware *encode* is the one GPU lever an ADR refuses
  (ADR-0143), and with it the ProRes hardware-encode preference.
- **No preview-file cache, and no smart rendering.** There is no equivalent of the render bar,
  Render In to Out kept as preview files, Use Previews at export, or smart rendering's
  pass-through of unchanged source. Every `render` paints and re-encodes every frame, and a
  partial render is a separate file nobody tracks. Render and Replace works, but only into H.264.
- **No live monitor.** Looking is call-and-return: a still, a contact sheet, or a proxy MP4.
  There is no real-time scrub, J-K-L shuttle or loop playback, no alpha or matte view, no
  two-up or split comparison image, no zoom above true scale, no guides drawn on a frame, no
  field display for interlaced footage, and no way to view a raw source file without a project
  around it.
- **No playback devices.** No audio hardware, no external video (Mercury Transmit, SRT, a TV via
  a deck), and no recording. Audio is always conformed to 48 kHz stereo, so the timeline's
  mono/stereo/5.1/adaptive mapping preferences have one fixed answer.
- **No preferences, by design.** Every "default" preference (transition and still durations,
  stroke join and cap, fonts, media scaling) is `missing` because Montagent never inserts: the
  value is written on the element. Preferences that are really substitutions (smart quotes,
  Hindi digits, emoji and missing-font fallback) are `have`, because runs are literal and a font
  key is an explicit fallback chain.
- **The Project panel is refused.** ADR-0002 rules out the media catalogue, its bins and
  project-only names; ADR-0017 rules out in-project labels, logging columns and custom metadata
  (a sidecar is the sanctioned route). Usage counts, paths and online status are `have` through
  `query --census source` and `validate`.
- **Collaboration is git, and only git.** There is no JSON-aware merge, no presence, no project
  or sequence locking, no cross-project reference (Productions), no review-and-comment loop on the
  *video* (Frame.io), and no shared asset library (CC Libraries). The remote instance (ADR-0159) is
  accepted but not in v0.2.0 (stdio-only transport). Detail in `workflow-collab.md`.
- **No automatic safety net inside a session.** Auto Save, the emergency backup and the History
  panel exist only at the granularity the agent commits.
- **Safe margins and accessible content are craft, not tooling.** The numbers live in
  `montagent-craft`. Nothing draws them on a frame, and no `validate` check enforces them.
- **Refused by ADR:** third-party video and audio plug-ins (ADR-0003, ADR-0017, ADR-0145),
  hardware encoding (ADR-0143), automatic updates (ADR-0064), the media catalogue and bins
  (ADR-0002), in-project labels and metadata (ADR-0017), a default paragraph direction
  (ADR-0133), automatic transcription (ADR-0051), and Reveal Nested Sequence (ADR-0001).
- **GUI-only rows (55):** workspaces, panels, menus, touch, Project panel views, keyboard shortcuts,
  monitor chrome (button editor, overlay layout, zoom bars, gang), and UI preferences. These are
  `missing`, because no ADR refuses a GUI. Assembly may want to group them.
