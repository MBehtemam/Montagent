🗳️ **Juror 3** (Claude Fable 5.1) — **Q10 VOTE: C — split the set into `document` and `disk`; a stopped run records `["document"]`**

**Reasoning:** The field is a scope claim, and the ratified rule is that it is *recorded as checks execute*. That rule was chosen precisely so the field never asserts a run that did not happen (`E-NOT-A-PROJECT`). The ffprobe case is the same situation one level down: the document checks did execute, the disk checks did not. Only C lets the field say exactly that. The halves are not an invention for the field's sake — the code already stops at that boundary, the comment already reasons about "two things learned", and the boundary is a real one (pure reads of the file vs. checks that need an external tool). Naming it makes the existing structure visible instead of hiding it inside one word. It also makes the already-decided `NOT CHECKED` rule work: "a generated scope sentence for any report that did not run the full `validate` set" needs the field to be able to express partiality, otherwise A suppresses the sentence (field says `validate`, so full set) and B generates a false one. One detail to fix at implementation: a project that references no media must record `disk` as run — the disk runner was entered, found nothing to probe, and completed — so that the no-media case is a complete run in the field, exactly as the question says it is, and only the ffprobe-missing case reads as partial. Prefer the split over a partial marker: a marker changes the field's type from a list of names into names-plus-state, and every consumer then has to know what "partial" means for each set; two names keep the field a flat list.

**Trade-offs:** A is the failure the whole feature exists to prevent — a report whose scope field claims the full set while the disk half never ran. Exit 70 and `E-TOOL-MISSING` mitigate it, but the originating incident was an agent truncating output, and the header is what survives truncation. B is the same lie in the other direction: `no checks run (validate runs them); 2 errors` above `E-RETIRED-KEY` findings that document checks raised is incoherent to the reader, and it contradicts the code's own stated reason for keeping those findings (tell the agent both things in one turn). What C costs: the glossary term ratified by two panels changes shape — `validate` becomes the verb's composite (`document` + `disk`) rather than a single set name, so the glossary entry, the prose header wording ("no checks run (validate runs them)" still works as prose since it names the verb, not the set) and the fmt/compare entries need re-reading for consistency; the field grows one more name; and the no-media run must be tested explicitly so it records both halves and is not misreported as partial.
