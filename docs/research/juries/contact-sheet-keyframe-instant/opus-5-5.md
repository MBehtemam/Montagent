🗳️ **Juror 1** (Opus 5.5) — **VOTE: Q1 (a) first painted frame at or after `t`, if `< e`; Q2 (a), and the population becomes grid-aware; Q3 (c), falling back to (a) with no finding; Q4 stays**

**Reasoning:**
- **Q1:** A keyframe marks where a change takes effect. The first painted frame at or after `t` is the first frame that shows the change. With a `step` ease, that frame shows the new value and the frame before shows the old one, so only (a) shows the step at all. It uses the same rule as the run tile (ADR-0094 §2), so a keyframe that sits exactly on `s` lands on the run tile's own frame. That is exactly why boundary keyframes were already counted as covered. The sample is always a painted millisecond, so `frame --at` / `query --at` reproduce it exactly. The offset from `t` is always less than one frame period and always forward, which makes it constant and learnable. "Nearest" gives no such guarantee: for a `step`, whether the new value shows depends on where `t` falls against the grid.
- **Q2:** One tile per distinct painted frame. Its provenance line lists every change point that maps to it, and each counts as `tiled`. When that frame is the run tile's frame, the tile stays a run tile: unmarked, keeping its boundary field, with the change points added to its provenance line. The population should become grid-aware. "Boundary keyframes are covered by the run tile" was justified because the sheet shows them. The same reasoning covers a keyframe at `s + 3 ms` whose sample frame is the run tile's frame. Calling it `untiled` without the flag would report a zero that isn't true. "Interior" should mean "maps to a painted frame other than the run tile's", not the raw test `s < t < e`.
- **Q3:** Under (a), if `t` is in the run's last partial frame period, the first painted frame at or after `t` is exactly the next run's tile frame. Being the next run's first painted frame is what defines that tile. So (c) is not a special case: it is the Q1 rule applied faithfully. If the element is still visible there, it counts as `tiled` by that tile. If it isn't (the boundary is the element's exit), or the next run is outside the range or has no painted frame, it counts as `untiled` with a reason and is disclosed only. There is no finding: off-grid keyframes are ordinary authoring, and the value keeps moving toward it on the frames before. `N-QUANTIZATION` is about a declared visible state never appearing on screen, not about a keyframe's exact value.
- **Q4:** Stays. The flag exists to tile instants the document states. Both #407 catches (the overshoot peaking at a keyframe, and the drift visible at its keyframe) were found at change points. An overshoot produced by the curve itself between keyframes is exactly what the `between-keyframes` blind spot already discloses: fixed, constant and learnable. Sampling at a curve extremum would bring back a derived instant, the kind of guessing the 3–0 vote refused. Nothing in this question changes the premises of that vote.

**Trade-offs:**
- **Q1(a):** The tile shows the value up to one frame period (40 ms at 25 fps) into the next segment, not `v` itself. For a fast segment that can be visibly past `v`. The blind-spot text should say keyframes are sampled at the first painted frame at or after `t`. (c) would be tidy against `frame --at` (the last frame starting at or before), but it never shows a `step` change and mostly duplicates what the run tile already shows. (b) mixes both behaviours in a way that depends on the curve's shape.
- **Q2(a):** A keyframe absorbed into a run tile is visible only on the provenance line (the census), not in the label or the mark. (b) would weaken the rule that the run tile is the unmarked baseline, and it would put the mark on a tile that isn't a keyframe sample. Making the population grid-aware means counts depend on `fps`. That is correct, because what the sheet can show depends on `fps`.
- **Q3(c):** The keyframe's tile appears under the next run, which can surprise a reader expecting it inside its own run. The provenance line must name the change point there. (b) would break the "at or after" guarantee and give a `step` the wrong side. (d) would flood findings on ordinary projects.
- **Q4 stays:** A curve-shaped overshoot or drift between keyframes, with correct endpoints, is still not caught. That is accepted as a disclosed blind spot, and a measuring verb is a better place for it than inventing tiles.
