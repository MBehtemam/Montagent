🗳️ **Juror 3** (Fable 5.1) — **VOTE: Q1 (a) ; Q2 (a), with a grid-aware tiled/untiled split over a raw-millisecond population ; Q3 (c), falling to (a) ; Q4 stays**

**Reasoning:**
- **Q1 (a).** A keyframe at `t` is a boundary between two easing segments exactly as `s` is a boundary between two visual states, and ADR-0094 §2 already answered "which frame shows a boundary": the first one the grid paints at or after it. Frames before `t` are governed by the *previous* segment (still approaching `v`); the first frame at or after `t` is the first one the segment that *starts at* `v` governs. That is the first painted frame on which the declared change has taken effect, and for `step` it is the only frame that shows the change at all — under (c) a step keyframe's tile always shows the old value, i.e. the flag would tile the instant and miss the change. The label's `<instant>ms` must be the painted millisecond (1040), not `t` (1013), with `photo-05.scale@1013` on the provenance line; `frame --at 1040` then reproduces it exactly, which the run rule already requires of run tiles. (b) buys at most one frame period of amplitude fidelity in exchange for a tie rule and a second rule shape; not worth it.
- **Q2 (a), grid-aware split.** One tile per distinct painted frame, provenance listing every change point that mapped there. The class token records *why the tile exists*: a run tile exists without any flag, so it stays unmarked and keeps its boundary field; (b) would make the same pixels change class depending on a flag. The population's *membership* stays a raw-millisecond test (`s < t < e`, element visible at `t`) — that is what the document states. But `tiled`/`untiled` is a claim about the sheet, so it must be grid-aware: a change point is `tiled` iff some tile of this sheet sits at its sample frame, flag or no flag, and the census names it on that tile. Reporting a change point as `untiled` when the run tile is literally its sample frame would be a false count.
- **Q3 (c), else (a).** Under Q1(a), if no painted frame lies in `[t, e)`, the least `n` with `⌊n·1000/fps⌋ ≥ t` is identical to the least `n` with `⌊·⌋ ≥ e` — the next run's own tile frame. So (c) never adds a tile and never invents an instant; it is just the Q2 grid-aware split applied across the boundary: if the element is visible there, the sheet already shows its post-`t` value and the census says so. If the element is not visible there, the value was never held on any painted frame: `untiled`, reason `no-grid-frame`, disclosure only. No finding, because an unpainted *run* is a declared visual state the video never shows (a structural lie), whereas an off-grid keyframe in an element's last partial frame period is the same ordinary quantization every off-grid keyframe suffers, already disclosed under `between-keyframes`, and the trimmed-move precedent already says an unseen keyframe is not a finding. (b) samples a frame the previous segment governs, showing a value the keyframe did not declare. (d) would fire on any keyframe within one frame period of an out-point — noise.
- **Q4 stays.** The flag exists to show the document's *stated* instants; #407's overshoot peaked at a keyframe because the author stated 1.85 there, not because the curve overshot. A curve-derived extremum (a `back` ease past its endpoint) is exactly what ADR-0094 refused 3–0 and what the `between-keyframes` blind spot already discloses as constant and learnable — "a wrong easing curve shows only if its endpoints are wrong" is the honest contract. The measurement strengthens the refusal: the tile sees amplitude, not shape, and a standard ease's overshoot is a few percent, invisible at 138 px anyway. If a peak tile is ever wanted, it should be a fourth opt-in class (`extremum`), not a reinterpretation of `keyframe`.

**Trade-offs:**
- Q1(a) samples up to one frame period *after* the peak (27 ms at 25 fps here) rather than the nearest frame; the curve has moved toward the next keyframe by that much. (c) would let `frame --at <t>` reproduce the tile directly under #387's last-frame-at-or-before rule, but at the cost of never showing a `step` change and showing the previous segment's value — a tile that does not show the keyframe's effect defeats the flag.
- Q2 grid-aware counting means `tiled` can be non-zero without the flag and run tiles' provenance lines grow keyframe entries; the counts are honest but the "zero is asserted without the flag" expectation becomes "the census is asserted". The alternative keeps the zero neat and lies by one whenever a keyframe lands on a run tile's frame.
- Q3(c) makes a run tile's census depend on keyframes from the *previous* run, which is a small conceptual leak across the boundary; the payoff is no invented instants, no extra tiles, and an `untiled` count that only names change points the video genuinely never paints.
- Q4 "stays" leaves a `back`/`elastic` overshoot between two correct endpoints invisible unless `infill` or a `frame --at` catches it; that is the disclosed blind spot, and reopening it would put a derived instant into the census the moment ADR-0094 finished excluding one.
