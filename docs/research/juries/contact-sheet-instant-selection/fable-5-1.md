🗳️ **Juror 3** (Fable 5.1) — **VOTE: One tile per visual state, where a visual state is a maximal run of the cut list over which the presence set restricted to `type != audio` is constant, sampled at the first grid frame whose painted millisecond (floor(n×1000/fps)) lies inside the run; runs that contain no grid frame get no tile and are named as skipped; keyframes and infill are opt-in flags, never defaults; and the answer carries a mandatory structured `selection` block plus a per-sheet `blind_to` list stating in words what the rule cannot see.**

**Reasoning:**

1. **Collapse rule.** ADR-0074 must be honoured literally: `query` keeps every element, audio included, and gains no `--visual` flag. The sheet's collapse is not a new `query` mode; it is `frame` doing exactly what ADR-0074 says a caller should do — filtering one field (`type`) of an answer it already has, then merging adjacent intervals whose filtered presence set is identical. That is the ADR's own prescribed ritual, executed inside `frame` rather than by hand, which is the whole point of the ticket. The one wrinkle: the collapse must be by *visual presence set equality*, not by "has any visual element", so two adjacent intervals differing only in which text card is up remain distinct. Elements the document does not place on the clock stay named in the answer (ADR-0074's second rule), under a `not_on_clock` field, never dropped.

2. **Where in the interval.** First grid frame inside the run, by ADR-0077's painted-millisecond formula. Not the midpoint, not the boundary millisecond. A boundary instant (`start` exactly) may be off-grid and would answer "what does the resolver say at a time the renderer never paints"; that is a question `query --at` already answers and it is not what a contact sheet is for. The sheet is the renderer's view, so it must sample instants the renderer actually paints. The first grid frame is preferred over the midpoint because it is deterministic from the document alone (no dependence on run length), it is the frame closest to the change the run represents, and a mid-run sample hides the transition that the run boundary exists to show. Each tile's label states the sampled ms and the frame index n, so the relation to the boundary is explicit.

3. **Keyframes.** Not by default. ADR-0035 says alignment is never the check and a keyframe's `t` is ordinary data; a keyframe is a *rate* change, not a *state* change, and presence-constant-transform-animating is the normal condition of any photo with a zoom. Tiling every keyframe on the fixture would roughly double the tile count and push served width below the ~180 px working point for no measured gain: a linear zoom does not produce a defect visible at a keyframe that is invisible at the run's first frame. However, the earlier juror is right that keyframe times are document-stated; so they earn a flag, `--at-keyframes`, which adds the first grid frame at or after each keyframe `t` of any visual element present, deduplicated against run starts, and the answer's selection block says `keyframes: included|excluded`. Easing midpoints are not document-stated points (they are derived from the curve) and get nothing.

4. **Intervals too short to see.** A run with no grid frame inside it (the 4 ms run at 56112–56116 at 25 fps: frames paint at 56080 and 56120, neither inside) gets no tile, because there is no frame to show; the renderer never paints that state. It is never silently dropped: it appears in the answer's `skipped` list with its bounds, its visual presence set, and reason `no_grid_frame`. This is the honest disclosure the ticket demands and it is also useful signal — a visual state the renderer never paints is exactly the kind of structural consequence ADR-0035 says to report as fact. If a run does contain a grid frame it gets a tile however short it is; brevity is not a reason to skip, only absence of a paintable frame is.

5. **Uniform infill.** Confirm: a flag, never the default. Specify it as `--infill <n>`, meaning "within each selected run, add up to n additional tiles at evenly spaced grid frames strictly between the run's first grid frame and its last grid frame", so infill never duplicates a boundary tile and never crosses a run. `n` is per run, not per sheet, so long runs get n extra tiles and a one-frame run gets zero; the answer reports how many infill tiles each run actually received. Infill tiles are labelled `infill` distinctly from state tiles so the agent cannot mistake a uniform sample for a document-stated boundary. Sheet-wide budget is separate: if the total tile count would push served tile width under the legibility floor, the answer says so and the caller narrows the range; infill is not silently reduced.

6. **The blindness, out loud.** Three forms, all mandatory, none optional:
   - A structured `selection` field: `{rule: "visual_state_first_grid_frame", visual_types: [...], tiles: N, skipped: [{from, to, reason}], keyframes: "excluded", infill: 0, tile_px: {w, h}, scale: 0.167}`. Machine-readable so the agent's next call can act on it.
   - A structured `blind_to` list of short fixed strings, e.g. `["changes inside a source clip (its own cuts, motion, mid-shot content)", "transform animation between keyframes", "any state shorter than one frame (see skipped)", "detail narrower than ~N px at this tile scale"]`. These are the rule's known blind spots as facts about the rule, not verdicts about the video, so ADR-0006 is respected. The last entry is computed from the served tile width against the measured ~140 px small-type cliff.
   - One sentence of prose in the answer body restating the rule and the count skipped, because the trial shows an agent reads the narrative and not just the fields, and the failure mode was silence in the narrative.

   No finding codes for the blind spots themselves: a finding implies something about *this* document, and the blindness is about the *rule*. Skipped runs do get a finding-class entry (`no_grid_frame`) because they are facts about this document.

**Trade-offs:** The rule costs the default sheet any view of what happens *inside* a run: a source clip's own hard cut, a subject moving out of frame mid-shot, a zoom that ends on a badly cropped face, a text card that is fine at its first frame and overlapped by a later element's motion. All of those need `--infill` or `--at-keyframes`, which the agent must think to ask for, and the `blind_to` list is the only nudge. It is blind to any state the renderer never paints (sub-frame runs), by design. Sampling the first grid frame rather than a settled instant means transitions with a fade-in will show the first frame of the fade (near-empty) rather than the settled card; the agent will see "empty" tiles that are not defects and may need a second call at a later instant — this is the price of determinism and of not inventing a "settled" heuristic that ADR-0035 would call a verdict. Collapsing inside `frame` duplicates a small amount of cut-list logic across two verbs (mitigated by sharing the registry's one data path). Finally, the whole design still cannot see the invisible-text defect as anything other than "a card with no visible text" — which the legibility measurements say survives at 92 px, but only if the agent knows the card is *supposed* to carry text, which it learns from the label's "what produced it", not from pixels. The `blind_to` list therefore has to stay a list of the rule's blindnesses and must not grow into a checklist that reads as coverage.
