🗳️ **Juror 1** (Opus 5) — **VOTE: Tiles are the document's own visual change points — the presence-boundary set filtered to visual types inside `frame` and re-merged, unioned with keyframe endpoints on visually-affecting properties — each snapped forward to the first frame the project's grid actually paints inside its interval; nothing is ever silently dropped, uniform infill exists only behind an explicit `--max-gap` flag, and every answer carries an unconditional structured disclosure of what the rule did not and structurally cannot see.**

**Reasoning:**

**1. The collapse rule — a filter inside `frame`, not a mode on `query`.** ADR-0074's reasoning applies here with full force and points the same way it did for the cut list: the visual narrowing "is a filter over the returned members, not a different question to ask." `frame` in range mode is exactly the caller ADR-0074 described — it already has the whole presence set, every member states its `type`, so it filters one field of an answer it already has. No `--visual` on `query`, no second `query` mode, no new term. Two consequences must be stated explicitly, because they are `frame`'s own work and not `query`'s: (a) dropping audio members makes adjacent intervals identical, and `frame` must **re-merge** them — the fixture's 46 intervals collapsing to ~14–18 is precisely this merge, and it is the operation, not the filtering, that does the work; (b) ADR-0074's other half — elements not placed on the clock are *named*, never silently dropped — carries over unchanged. The answer names the audio (and other non-visual) elements it filtered out and the intervals it merged. An agent must never be able to read this sheet as "these are all the elements."

**2. Where the instant falls — first frame on the project's own grid, snapped forward.** Not the midpoint. Three reasons. First, reproducibility: the tile must be a frame the renderer would actually emit, so the agent can re-call `frame --at <that ms>` and `query --at <that ms>` and get identically the same pixels and the same stack. A midpoint is a synthetic instant nobody else in the tool computes. Second, ADR-0077 gives the arithmetic for free: pick the least frame index n with floor(n × 1000 / fps) inside [start, end), and paint at that millisecond. Third, ADR-0035's point cuts exactly this way — the off-grid boundary time is meaningful data and must appear in the label, but it is not a renderable frame, so the tile's instant and the interval's start are two different numbers and **both** are printed. The tile answers "what is settled here", the label preserves "what changed at here". A boundary instant and a settled instant answer different questions; the sheet shows the settled one and names the boundary one.

**3. Keyframes — endpoints yes, interpolated midpoints no.** A keyframe's `t` is a document-stated change point in exactly the sense a start or end is, and "presence constant while a transform animates" is the load-bearing trap restated: a rule that only watches presence goes silent across the fixture's zooming photos and that silence reads as coverage. So the boundary set is the union of visual presence boundaries and the `t` of every keyframe on a visually-affecting property of an element visually present at that instant, deduped after grid-snapping. But I reject the earlier juror's easing midpoints: an easing midpoint is not stated by the document, it is interpolation, and inventing instants is the guessing this feature exists to replace. Tween start and end are stated; what is between them is not. When keyframe-derived tiles must be dropped for budget they are dropped as a **named class** with a count, never thinned invisibly.

**4. Sub-frame intervals — no tile, always named.** The 4 ms interval at 56112–56116 contains no grid instant at 25 fps (frames land at 56080 and 56120). It cannot produce a frame, so it gets none — but it enters the structured `skipped` list with its bounds, its presence-set delta and reason `no-grid-frame-in-interval`. This is ADR-0074's "named, never silently dropped" applied to instants rather than elements, and it is also the interesting fact in its own right: the document states a state the rendered video never shows. Reporting that is `validate`-shaped fact, not verdict, so ADR-0006 permits it and forbids calling it wrong.

**5. Uniform infill — confirmed as a flag, and it should be a gap ceiling, not an `--n`.** Reject `--n` per interval: it spends the same number of tiles on a 200 ms interval and a 20 s one. Specify instead `--max-gap <ms>`: after the boundary set is fixed, insert grid instants so no two consecutive tiles are further apart than that. Four constraints make it safe. It is off by default. It is strictly additive — it can never displace a boundary tile. Every infill tile is labelled `infill` in a different register from `boundary`/`keyframe`, so the agent can never mistake "the document said something changed here" for "the tool guessed here". And infill tiles are the first class evicted under the tile budget. This is the one place uniform sampling is legitimate — defects the document cannot predict, a source clip's internal cut, motion within a shot — and it is legitimate only because the caller asked for it and the answer labels it as a guess.

**6. The blindness — a structured field, present unconditionally, prose alongside.** The trial's failure was not that a caveat was absent; it was that nothing forced the agent to reconcile its coverage claim with its rule's reach. Prose alone is the `preview` ladder's precedent and it is not enough here, because the reader is a machine that will summarise. So every range answer carries, always:
- `rule` — the named rule and its version, so a claim of coverage cites something falsifiable;
- `tiles[]` — instant_ms, source interval, `why` (`presence-boundary` | `keyframe` | `infill`), the elements that produced it, and the **served** tile width in px;
- `skipped[]` — every interval with no tile, with reason (`no-grid-frame-in-interval`, `budget`, `merged-identical-after-visual-filter`);
- `coverage` — total ms in range, ms lying inside an interval a tile represents, and an explicit `ms_not_depicted`;
- `blind_to` — a **fixed, static** enumeration emitted on every answer, never conditionally: change the document does not state (a source clip's own cut, video/animated-source content motion), anything strictly between two tiles, anything finer than the served tile width (naming that width in px and saying small type may not survive it), and anything that exists only as a relation between frames not both on this sheet.

The unconditionality is the whole mechanism. A caveat that appears only when something went wrong teaches the reader that its absence is an all-clear, which is the trial failure reproduced inside our own tool. Correspondingly: when the boundary set exceeds the tile budget, degrade served tile scale to the floor first, and if it still does not fit, **refuse with a code** naming the sub-ranges that would fit (ADR-0021's ladder, refusal rung) rather than serve a thinned sheet that looks complete. Silently shrinking the boundary set is the one thing this feature must never do. None of these fields judge anything — `blind_to` describes the rule, `skipped` describes the document; no scoring, no "tile 7 looks wrong" (ADR-0006).

**Trade-offs:**
- **Cost.** Keyframe endpoints inflate tile counts on animation-heavy documents; on a project where every element zooms, the boundary set can exceed the ~18-tile / ~180 px working point and the caller is pushed into splitting the range. That is the correct failure — a refusal that says "ask for less" beats an illegible sheet — but it means range mode will not always be one call, and the "one call instead of N" promise holds for the fixture and not universally.
- **Complexity in `frame`.** The re-merge after the visual filter is real logic living in `frame` rather than `query`, and it must stay consistent with `query`'s presence-set semantics or the two verbs will disagree about what a boundary is. That is the price of honouring ADR-0074 rather than bypassing it, and it needs a cross-verb test.
- **Blind by construction to:** anything the document does not state — a source clip's internal cut, content motion inside a still-looking element, a corrupt frame mid-file (only `--max-gap` reaches these, and only by luck); anything finer than ~180 px of served width, which per the measurements includes small type — the invisible-text defect survived only because absence-of-text-on-a-card is a large-area cue, and a *subtly* miscoloured caption would not; motion and timing feel, which stay with `preview` by design; audio entirely; and anything that is a relation between two instants not co-present on one sheet — the wrong-photo defect was caught because both photos landed on the same image, and a range split across two sheets loses exactly that.
- **The residual risk I cannot design away:** an agent can still paraphrase a disclosed sheet as "I checked the whole range." The structured `coverage` and `blind_to` fields make that paraphrase contradicted by the answer it came from, which is the most a tool can do; they do not make it impossible.
