🗳️ **Juror 2** (Sonnet 5) — **VOTE: A sheet tile is emitted at the first on-grid frame of every interval where the visual-type-filtered presence set changes OR a keyframe of a currently-present element fires, plus the boundaries of any interval below one frame's duration collapsed into their neighbor and named as skipped, with all of this stated as a filter over `query`'s existing answer, never a new mode.**

**Reasoning:**

1. **Collapse rule.** Filter, not a mode — and it lives in `frame`'s range-mode handler, not in `query`. ADR-0074 already settled that "visual" is not a first-class distinction the answer format should encode; it's a filter over `type` applied by whoever wants it. `frame`'s range mode wants it, so `frame` computes the cut list via the existing `query --from --to` primitive internally, then filters members by `type` to decide *which boundaries produce a tile*. This is exactly the caller ADR-0074 anticipated — it doesn't reopen the ADR, it exercises the escape hatch the ADR built. Audio-only boundaries still exist in the underlying interval data and must be named (see #6), just not tiled.

2. **Instant placement.** First frame on the project's own grid, via ADR-0077's floor(n × 1000/fps). Midpoint answers "what does this state look like at its most settled," which is a judgment call the tool shouldn't make (ADR-0006: facts not verdicts). First-frame-on-grid answers "what does this interval's onset look like," which is the same posture `frame --at` already takes toward any instant, and it's reproducible without picking a fractional convention. Boundary-first also makes a defect that appears exactly at a cut (the wrong-photo swap) visible at its earliest instant rather than smoothed into the interval's middle.

3. **Keyframes.** Yes — a keyframe instant earns a tile, on-grid-snapped like any other. Presence-constant-but-transform-animating is exactly the class of "document-stated change point" the destination's own language ("visual-state boundaries") should include; refusing it would silently privilege presence over every other authored change, which is arbitrary. I reject extending this further to tween easing midpoints and generic start/end pairs beyond the keyframe's own stated instant — those are derived, not authored, and adding them reopens the door to the uniform-sampling instinct question 5 forecloses. Keyframes are cheap to enumerate (they're already in the document); easing curves are not a bounded set.

4. **Sub-frame intervals.** The 4 ms interval gets no tile of its own — it cannot produce a distinct frame at the project's fps — but it is not silently dropped. It's merged into its containing on-grid frame's interval for tiling purposes, and named in a disclosed "collapsed" list with its original bounds and cause (duration < one frame). This mirrors ADR-0074's rule that elements outside the clock are named, never dropped, extended to intervals too short to render.

5. **Uniform infill.** Confirmed as an opt-in `--n`/`--every` flag, off by default, and — critically — its output tiles are visually distinguished (labelled "sampled," not "boundary") from document-derived tiles so an agent cannot mistake density for coverage. This is the single most important guardrail given the trial: the failed agent's fatal error was treating a sampler's silence as coverage. If we ship uniform sampling with the same label as boundary-derived tiles, we reproduce the failure inside the sheet itself.

6. **The disclosure.** A structured field, not just prose, because prose is exactly what the failed agent's own summary was and it still misread coverage as complete. The answer includes: the selection rule name/version, total intervals in the underlying cut list, how many became tiles vs. were collapsed (with their bounds and reason), the tile scale/served width actually used, and an explicit machine-checkable list of defect classes this method cannot see — starting with "no comparison across tiles is performed; relational defects (e.g., a substituted asset that is internally coherent) are not flagged" and "keyframe interpolation between two keyframes is not sampled; only keyframe instants themselves are." Prose disclosure duplicates this for a human reader but the structured field is what stops an agent's own coverage claim from outrunning what was actually looked at.

**Trade-offs:** This rule is blind to: (a) anything that changes strictly *between* two adjacent authored boundaries with no keyframe of its own — a source clip's internal cut, a lighting change baked into footage, motion blur artifacts; (b) tween interpolation frames between keyframe endpoints (a bad easing curve won't show unless start/end themselves are wrong); (c) relational defects like the wrong-photo swap remain detectable only if the tile is large enough to be *recognized as wrong* by content, not because the sheet does any comparison — the sheet still does zero verdict work, so this stays an eyeball task for the agent. Cost-wise, keyframe inclusion on a heavily-animated document could push tile count well past the ~18-tile working point for legible width; that's an explicit trade this rule takes knowingly, disclosed via the "N boundaries selected before shrinking" field, rather than silently thinning keyframes to hit a budget (which would reintroduce hidden blindness). The 4ms-merge rule means an authored instant that happens to fall inside a collapsed micro-interval never gets its own tile even if it was intentional — it is named as collapsed, not rendered, which is a real loss disclosed rather than hidden.
