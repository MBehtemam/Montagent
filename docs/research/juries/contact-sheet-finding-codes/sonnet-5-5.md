# Juror 2 — Sonnet 5.5

Recorded verbatim, unedited.

🗳️ **Juror 2** (Claude Sonnet 5.5) — **VOTE: Q4 (b) new dedicated code, class review; Q5 (a) with the disclosure items as disclosure, sheet points at `frame --crop --at`; Q6 (a) with a constructed test document**

**Reasoning:**

Q4: I vote (b), a new code emitted at `review`. N-QUANTIZATION is defined as what snapping times to the frame grid changes for elements. Its template, "changes {changed} boundaries", and its two escalation conditions are about elements vanishing or same-track overlaps and gaps. A visual state that never reaches the screen is a different fact. It is a property of a span, not of an element, and it comes from cross-track boundaries. Stretching the code to cover it would blur its contract. ADR-0006 says a code is the handle for suppression and the identity that `compare` diffs on. Suppressing N-QUANTIZATION should not also hide "a declared combination is never shown." Option (a) also makes `frame` claim a code that `validate` does not yet raise, which is a code with two behaviours depending on the verb. A new code, whose name is left to the implementers, keeps the contract clean. If `validate` later detects the condition, it can share that code. Review is the right class. The declared state never appears, so the frames do not show what the document declares. That is the same reasoning ADR-0006 uses for the "rounds out of existence" case, and it fits the definition "you must look at a frame to judge it." A note would understate it. ADR-0094 was right that a skipped run is a fact about this document, and the code names that fact. The `validate` gap should be filed as separate work.

Q5: I vote (a). `blind_to` describes the rule, not the document, so it is the sheet's analogue of NOT CHECKED. It should be a fixed list of stable lowercase kebab tokens with no letter prefix, and each token should have one fixed prose sentence. The prose is required by ADR-0097 for the plain-text answer. Option (b) is wrong. It would put U- findings on every answer, and a finding that appears unconditionally says nothing about the document. That contradicts ADR-0094's "no finding code for a blind spot." Option (c) gives up identifiers that agents and a future `compare` could key on. The other disclosure items are also disclosure, not findings. These are the dropped audio-only boundaries (count and list), the count of untiled keyframe change points, the served tile width and the budget rung that produced it. They describe how the rule was applied. They are not defects in the document. The exception is `skipped` runs, which are document facts and carry the code from Q4. Yes, the sheet should point at `frame --crop --at <instant>`. Putting it in the `below-tile-width` sentence is cheap and puts the two-step loop in front of the agent on every sheet. ADR-0103 only requires the refusal to name the loop. Because the sheet is the place an agent first sees a blurry tile, the pointer belongs there as well. I would keep it in that one sentence rather than as a separate line.

Q6: I vote (a). The example in §4 was computed before the re-merge that the same ADR mandates. It is a factual error in a ratified record, and the precedent (the §3 correction) shows the project handles this by recording the correction in the ADR. A comment on the ticket is easy to lose, and the ADR is the reference that later readers rely on. A small re-executable script that recomputes 46 → 18 runs and zero instances makes the correction checkable. Zero instances on the only fixture does not change my Q4 answer. The condition is still possible, since two visual boundaries on different elements less than one frame period apart is a valid document. The rule is cheap. However, the code should not ship without a constructed test document that has an instance. Without one, the emission path, the prose rendering and the `skipped` shape would go untested. The fixture cannot test them.

**Trade-offs:**

Q4: A new code adds one more entry to the code table and leaves `validate` and `frame` unaligned until the follow-up work lands. Reusing N-QUANTIZATION (a) would be less to maintain, but it widens a contract that was written for elements. A note class (or no finding, option c) would leave the never-painted state below the level of "look at a frame," so I rejected those.

Q5: Free prose (c) is simplest but gives nothing stable to reference. U- findings (b) would clutter every answer and blur what a finding is. The cost of (a) is a second stable-token vocabulary that must be maintained beside finding codes. It is small, and it is the right separation.

Q6: Amending the ADR and committing a script costs a little more work and one more file in the repo. Option (b) is cheaper but leaves the ADR with a wrong example, and the record would be inconsistent with the §3 precedent.
