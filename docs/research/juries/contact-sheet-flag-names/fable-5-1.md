# Juror 3 — Fable 5.1

Recorded verbatim, unedited.

---

🗳️ **Juror 3** (Fable 5.1) — **VOTE: Q1 (a) ; Q2 `--keyframes`, bare boolean, MCP `keyframes` ; Q3 (a) `--infill <MS>` ; Q4 coin "infill ceiling", retire "gap ceiling" ; Q5 (a) ; Q6 (c) ; Q7 (a) ; Q8 yes — adopt the interior-and-visible definition; report `tiled` and `untiled` both, always ; Q9 (a) ; Q10 agree (a), agree (b), agree (c)**

**Reasoning:**
- Q1: Off by default, and the caveat is now retired by evidence rather than by its absence. The measurement did produce evidence on both sides — zero interior keyframes on the real project, two of four defects caught on the constructed one — but the deciding rule is ADR-0103, not the numbers: (b) makes the sheet's blindness to keyframed interiors depend on how many states happen to fit at 140 px, so the same document is blind on a 20-state range and sighted on a 12-state one. That is exactly the per-call-varying blindness ADR-0103 refuses. (c) would let a passive default push a working call into `E-SHEET-OVERFLOW` (the 13th keyframe tile), which converts a refusal the caller asked for into one they did not. `between-keyframes` stays a constant, learnable token under (a).
- Q2: `--keyframes`. It is the bare-word boolean the CLI already uses (`--full`, `--census`), it has no `--with-`/`--include-` prefix the project has nowhere else, and it is literally the ADR-0098 §6 class token — the flag names a tile class it adds, not a rule it switches to. `--per-state`/`--each-cut` failed because they named selection; `--keyframes` names a population, which is additive by construction. No value: there is nothing to size (arity is derived, the budget is width).
- Q3: `--infill <MS>`. Same argument: it is the other class token, units stay out of the name and in `value_name = "MS"`, and help text states "ceiling". `--max-gap` is rejected because **Gap** is already a glossary term meaning a track stretch with no element, and the sheet's infill has nothing to do with track gaps; the collision would be read as "the longest track gap to tolerate". `--infill-every` reads as a period, which is the `--n` mistake wearing a duration. `--infill-ceiling` is correct but says in the name what one word plus help text already says, and would be the only hyphenated compound among the verb's flags.
- Q4: Coin **infill ceiling**: "the longest span of the range a sheet may leave unsampled; infill tiles are inserted until no two consecutive tiles are further apart than this." "Gap ceiling" must go because of the glossary collision above — a term of art that overloads an existing glossary word inside the same tool is worse than a new one. The name also lines up flag, class token and provenance register on one word.
- Q5: (a). ADR-0094 §5 says infill is "the first class evicted under budget" and "can never displace a document-derived tile". The degrade step *is* the budget acting; if infill could trigger it, requesting infill would take 40 px from every document-derived tile, which is displacement in the only currency ADR-0095 counts. So the rung is fixed by the document-derived tiles (plus keyframe tiles if the flag is passed, since those are document-derived too); infill fills the slots that rung leaves. Corollary worth stating: on a range whose document tiles already fill the target rung, infill yields zero tiles and says so — a null result, not a refusal.
- Q6: (c). (b) produces a ceiling that holds in some stretches and not others, which is a blindness varying within a single answer — the worst case of ADR-0103. (a) throws away a fit that was available. (d) contradicts §5's own text (eviction is "disclosure only, no finding", "the instrument's own choice, like the rung"). (c) keeps the promise uniform: "requested 2000 ms, achieved 3000 ms", achieved being the actual max spacing of the served sheet, the would-have-been tiles in `skipped[]` as `infill-evicted`. A constant, disclosed, learnable degradation.
- Q7: (a). ADR-0098 §8 defines the identifying field as "what changed at this run's own boundary"; a tile with no boundary has an empty field by definition, not an elided one, so it cannot participate in the fit without corrupting the sheet-wide rule (the measurement showed one 19-char `element.property` stripping the field from every document tile). The sigil and class mark already say what the tile is; `photo-05.scale` belongs on the provenance line, where the census lives. (b) makes the busiest sheet the one most likely to lose its pointers; (c) invents a second abbreviation register the label spec does not have.
- Q8: Yes. The §3 count exists so the caller can judge what the sheet did not show; a count that prints 14 where the sheet is blind to 0 is the "noise read as a gap" the measurement named. Keyframes on a run boundary are already tiled, and keyframes outside the declaring element's lifetime are not a sheet matter at all (a trimmed move is legal and documented; if it deserves a finding, that is `validate`'s). Report both `tiled` and `untiled` every time, flag or no flag, so the zero is asserted the way `0 keyframe, 0 infill` is: without the flag `tiled: 0, untiled: N`; with it `tiled: N, untiled: 0` (or the refusal). Two numbers whose sum is constant across the two calls is the shape a caller can check.
- Q9: (a). Without the field, the caller sees sub-ranges that fit and concludes the range is too long, when the actual remedy is to drop the flag; the existing fields cannot distinguish the two. The field should say the range fits without `--keyframes` and how many keyframe tiles the floor would admit, rendered in prose too. (c) is ADR-0095's forbidden thinning by another name and reintroduces Q1(b)'s per-call blindness.
- Q10: Agree with all three. (a): MCP already takes the bare CLI word; `keyframes` and `infill` need no translation. (b): "the pair *is* the mode", and the precedent (`--at` with `--from/--to` is bare `E-INVOCATION`) makes a mode-flag-without-the-mode the same error class. (c): a clamp answers a question the caller did not ask; below one frame period there is no frame the grid can paint at that spacing, so the request is malformed, not merely tight. Note a ceiling longer than the range is *not* an error — it is a legal request that adds zero tiles, and the answer says so.

**Trade-offs:**
- Q1(a) leaves the constructed project's two real catches (scale overshoot, off-canvas drift `validate` never flags) behind a flag an agent must know to pass; the disclosed `untiled` count and the `between-keyframes` token are what carry that knowledge. (b) would have made those free on light projects, at the price of a blindness nobody can predict from the document alone.
- Q2/Q3 bare class-token names put the "ceiling, not a count" semantics entirely in help text; `--infill-ceiling` would have made it self-describing at the cost of breaking the verb's naming pattern.
- Q5(a) means infill is often a no-op on dense ranges (an 18-state 9:16 range has no slots at 180 px); (b) would have made it more often useful, at the cost of a flag that silently shrinks every document tile.
- Q6(c) requires the implementation to search for the achieved ceiling rather than just truncate; the payoff is one number that describes the whole sheet.
- Q7(a) means a keyframe tile's label carries no element name at all; the reader must go to the provenance line. The alternative — one long id thinning every label — costs more.
- Q8 both-counts costs one extra number on every answer; the alternative is a count whose meaning changes with the flag.
- Q9(a) adds a field to a refusal that already has several; the alternative is a correct refusal that steers callers to the wrong fix.
- Q10(c) refusing rather than clamping is stricter for callers; the alternative is a served sheet that quietly did something other than what was asked.
