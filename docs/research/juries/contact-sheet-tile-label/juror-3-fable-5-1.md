🗳️ **Juror 3** (Claude Fable 5.1) — **VOTE:**
Q1: (a) gutter strip beneath the tile, 11%, as measured.
Q2: (c) both, with the visual treatment load-bearing on the sheet and the textual register carried on the provenance line, not the label; document-derived tiles are unmarked, but the sheet's text output must state the count of each tile class present, including zero.
Q3: Full presence set on every line; no delta.
Q4: Fixed arity, with an explicit placeholder glyph when a field has no value; never drop a field.
Q5: Yes, a floor of 8 px served type (named constant, flagged as a perceptual claim like the others); if content does not fit at the floor, truncate only the variable id field with a visible ellipsis, never shrink further and never silently drop.
Q6: No. The boundary stays; the arithmetic argues for printing it compactly, not for omitting it. The only field that may give is the id.
Q7: (c) the tool vendors its own permissively licensed UI face (ASCII-plus subset, embedded in the binary), with a visible replacement glyph for unsupported characters.
Q8: The label names the change at the run's boundary, signed: "+id" for the topmost-layer element that entered at that boundary; if nothing entered, "−id" for the topmost-layer element that departed; for a tile whose boundary is the --from clip rather than a document change point, an explicit neutral sigil plus the topmost-layer element present that does not span the entire document.

**Reasoning:**
Q1. The feature's entire justification is defects visible only in pixels. An overlay burns label pixels over exactly the region where small captions live (the fine-detail class that already dies at 140 px). The gutter is measured, is already inside the 180/140 geometry, and moving it reopens the cliffs. Occluding image content to save sheet area trades the thing the tool exists to show for the thing it exists to annotate.

Q2. A one-glyph prefix costs ~4% of a 25-char label, so cost is not the deciding factor; robustness is. Colour and border treatments survive downscaling and survive a label that has been truncated or is at floor, so the visual mark is what must be load-bearing on the image. But a picture-only mark cannot be grepped or quoted, so the provenance line carries the class as a text token, where width is free. Document tiles should be the unmarked default because the mark is a warning, and a warning on every tile is no warning; however "absence of mark" is precisely a silence, so the text output must assert "0 infill, 0 keyframe" explicitly when that is the case. That converts absence from inference to statement, which is the whole lesson of the trial.

Q3. A delta forces the reader to fold state across lines to know what is on screen at tile 7. That reconstruction step is exactly where a wrong attribution enters, and the brief has already established misattribution is a per-tile hazard. Full sets cost roughly 18 × 120 ≈ 2.2k characters, nowhere near the 28k that motivated the split. The delta was a width remedy for the label; the list has no width problem.

Q4. Fitted-to-width means arity variance becomes type-size variance, and the measured 1.46x spread lands the smallest type on the busiest tile. Worse, a dropped field reads as "nothing here", which is the silence-as-coverage failure. Fixed arity with a placeholder makes "no value" a positive statement.

Q5. "Fits" without a floor is how 1.4 px happened; a label that technically fits but cannot be read is a silence dressed as a label. 8 px sits above the single-primed-observer 6.3 px figure and, by the measured law, admits ~28 chars at 140 px and ~36 at 180 px, enough for index + instant + boundary + a signed id. The fixed numeric fields (16 chars) always fit at 13.4 px or better, so only the id can ever be the overflow, and truncating it with an ellipsis is honest because the full id is one lookup away on the provenance line keyed by tile index.

Q6. This is an upstream constraint and I would not reopen it, but the merits agree: an agent seeing only the instant will assume it is the boundary and reason about the run from the wrong millisecond. The sub-frame delta argument shows the boundary is cheap to print (it can be printed as instant plus a signed offset if width ever mattered), not that it is dispensable. Width pressure comes from the id, so that is what yields.

Q7. The project font may be Thai-only, digitless, or missing from disk, and the label needs digits and Latin ids; using it would make the label's legibility depend on the document under inspection. A system font varies across six targets and headless CI, which breaks re-derivability of the 295/chars law. A vendored OFL-licensed face costs a license file in the repo and some binary size, and buys deterministic metrics everywhere. The prototype's fixture-directory font was an accident and must not become the design.

Q8. The rule must be a function of (document, boundary instant) only. Run boundaries inside the range are document change points, so "what entered at this boundary" is range-independent and automatically excludes always-on chrome, which never enters after t=0. Layer order is the only sanctioned tie-break and topmost is also the element most likely to be visible on top, so it is both legal and useful. A departure-only boundary has no entrant, and naming a present element instead would be arbitrary; naming the departed element with a minus sign gives the reader a positive expectation ("this should be gone") that is as detection-load-bearing as "this card should carry text", and the sign prevents the misattribution hazard of naming an absent element. The clipped first tile is the one unavoidable range-dependent case; making its sigil distinct says so rather than pretending otherwise, and excluding whole-document-span elements keeps it from naming chrome.

**Trade-offs:**
Q1 costs 11% of tile height permanently and forgoes nothing else; (b) would save area but the saving is paid in exactly the pixels the fine-detail defect class needs. Q2 costs two conventions to learn (a visual mark and a text token) and a label glyph; pure (a) would die first when the label is at floor, pure (b) would be unquotable in text and invisible to an agent reading only the provenance list. Q3 costs ~800 extra characters per sheet of repeated chrome ids; the delta would save them at the price of a mental fold per tile. Q4 costs a placeholder glyph on tiles that have nothing to say, and forbids a richer label on tiles that could afford it. Q5 costs some labels an ellipsis, and the 8 px figure is itself an unverified perceptual claim that should be re-measured with a naive observer; without a floor the label degrades to noise with no signal that it did. Q6 costs 6 or 7 characters per label that are numerically redundant to within a frame; dropping them would save type size but manufacture a false equality. Q7 costs a licence obligation and binary size, and the label will not match the project's typography; (a) fails on real projects, (b) fails on reproducibility. Q8 costs a clipped first tile with a weaker field, and a departure-only tile that names something not on screen (mitigated by the sign); the range-relative "not in every tile" definition would give better discrimination per sheet but the same instant would then label differently across calls, which is the same kind of synthetic, irreproducible output the midpoint was rejected for.
