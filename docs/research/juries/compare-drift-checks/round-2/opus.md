🗳️ **Juror** (Opus) — **VOTE: R2-Q1 = No, don't narrow to keyframe-only; but boundary-vs-boundary gets a short delegation-plus-named-gap subsection, not a parallel full design. R2-Q2 = In scope — the ADR-0036 exclusion was about a presence census and does not transfer to a destruction diff. R2-Q3 = Option B.**

**Reasoning:**

**R2-Q1.** Slack and coincidence are not the same concept, and the difference is load-bearing, not cosmetic. Slack is a *min-aggregate over partners* ("distance to the **nearest** neighboring boundary in any track, or to `duration`"); coincidence is a *pairwise relation*. Where an endpoint coincides with two or more other boundaries — likely common in a file where 92 of 120 endpoints (76.7%) coincide with at least one other — destroying one of those pairings leaves the min at 0, and slack-drift reports nothing. A moves off B but stays flush with C: slack invariant, coincidence destroyed, `compare` silent today. Slack also can't distinguish *which* partner it is measuring against, so a partner swap at constant distance 0 is invisible to it by construction.

So the honest framing is: slack-drift already mechanizes the single-partner case, which is the majority of boundary coincidence; the residue is multi-partner clusters. That residue is real but is a different shape of work from (a)/(b)/(c), and I'd rather the ticket **state the overlap precisely and either mechanize or explicitly defer the cluster residue in one named paragraph** than either (i) silently drop boundary-vs-boundary as "already covered" — which would be a false claim in the ADR record — or (ii) spend the ticket's design budget re-deriving a check that ADR-0032 already ships. This follows R1-Q1's own precedent: Fable's point that fixed-offset must be named as deferred fog rather than silently dropped applies with equal force here.

**R2-Q2.** ADR-0036 excluded self-keyframe-on-own-boundary from a *`validate` census* because flagging the mere presence of a structurally-correct pattern adds no information. That rationale is entirely about presence. `compare` doesn't report presence; it reports *destruction* — a relationship that held in the reference version and doesn't now. "This keyframe used to sit exactly on its element's start and no longer does" is not a restatement of benign structure; it is a report that something changed, and it is precisely the silent-breakage shape `compare` exists to catch: the photo's start moves, the Ken Burns ramp doesn't follow, the zoom now begins mid-shot. A benign *state* can have a non-benign *transition*; ADR-0036's reasoning never addressed transitions.

Two supporting facts. First, this case is self-contained — one element, one property, no cross-element inference of intent, so it carries none of the ADR-0039 failure mode that sank the validate-side coupling check. Second, it is the **only populated case in the real fixture**: all 7 keyframed elements exhibit it, and cases (b) and (c) have zero live instances. Excluding it would leave the destroyed-coincidence check with no real-data coverage at all — nothing to test against, nothing to measure noise on, and nothing it would ever have fired on in the project's actual history.

**R2-Q3.** Option B. The predicate for (c) is the same predicate as (a)/(b) — per-property, delta-0-in-ref, nonzero-in-current — so "full rigor" and "design the mechanism" are not meaningfully different amounts of design work here; the increment is one paragraph of epistemic honesty, not a reduction in engineering. What is genuinely unknown is noise behavior, and the fixture gives zero evidence either way: zero cross-element same-property keyframe matches means the check is guaranteed silent on the only real data that exists. Silence on a population of zero is not a false-positive measurement. Given that the validate-side ancestor of exactly this check false-positived on 5/5 real correct groups, and given the project's repeated history (frame-alignment rules, the "sequence" label) of theory-only designs turning out wrong on contact with data, the ADR must record that this arm ships unmeasured, and ideally name the trigger for revisiting it — the first real project containing genuine coupled motion, or the first reported false positive.

**Trade-offs:**

- **R2-Q1** costs a paragraph of ADR text describing an overlap rather than a clean "out of scope" line, and leaves the multi-partner cluster residue possibly unmechanized. The alternative — declaring boundary-vs-boundary fully covered by ADR-0032 — is cheaper to write but puts a subtly false equivalence into the permanent record, which is worse in a project whose entire premise is that the file and its documents must be understandable by reading them.
- **R2-Q2** costs the risk that shifting an element without its keyframe is *deliberate* re-timing, producing a report the author didn't need. But `compare` has no severity (settled at R1-Q3) and is purely descriptive, so the cost of a report that the reader dismisses is one line of prose — far below the cost of the silent-breakage case it catches. Excluding it costs the check every live example it has.
- **R2-Q3** costs an ADR that admits a gap, which reads as less finished than Option A. Option A's confidence would be borrowed rather than earned: identical code, but a record that implies validation the project never performed — and that is precisely the mistake the frame-alignment and "sequence"-label episodes already charged for.
