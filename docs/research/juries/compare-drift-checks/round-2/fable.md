🗳️ **Juror** (Fable) — **VOTE: R2-Q1: Yes, narrow to (a)/(b)/(c) — but the ADR must record that slack and coincidence are not the same concept, and name the boundary-vs-boundary gap as deferred fog rather than claiming slack-drift covers it. R2-Q2: In scope — self-pairs are the *strongest* candidate for the destroyed-coincidence check, not the weakest. R2-Q3: Option B.**

**Reasoning:**

*R2-Q1.* Slack is a **min** (distance to the *nearest* boundary); coincidence is **pairwise**. They agree only when an endpoint has exactly one coincident partner. With 92/120 endpoints coincident and scene cuts typically stacking photo-end = caption-end = vo-end, many endpoints have two or more partners. If one partner moves and another stays, slack remains 0 and slack-drift reports nothing — yet a coincidence was destroyed. So "coincidence = slack of size 0" is true for the *presence* question and false for the *destruction* question. That said, the residue slack misses is a boundary-only refinement of an already-shipped check, and the existing grouped-delta output (`19 of 20 elements at/after 30603 moved +800 ms; vo-quiz-answer did not`) already surfaces the common shape of it. It does not belong in a ticket whose novel content is keyframe instants. Narrow the ticket; write the gap down.

*R2-Q2.* ADR-0036's exclusion was about a *presence census* in `validate`: a keyframe sitting on its own boundary is definitionally correct authoring, so counting it adds nothing. This ticket asks a different question — *did a relationship that held stop holding?* — and for self-pairs the prior state is the strongest possible evidence of intent: nobody accidentally puts the Ken Burns ramp at exactly `start`. Keyframe `t` is absolute in this file (photo-05: start=3018, t=3018), so a raw hand-edit of `start` without touching `t` leaves the ramp beginning before the photo exists — silent, invisible to slack-drift, and exactly the hazard `compare` is the backstop for. It is also the only case with a live population (7/7). Lowest false-positive risk of the three, highest real-fixture coverage. Excluding it would drop the one case we can actually measure.

*R2-Q3.* The predicate is the same across (a)/(b)/(c) — typed instants, delta 0 in ref, nonzero in current, keyed per-property. Designing (c) is nearly free *as mechanism*; what is not free is any claim about its noise on a real coupled-motion project, because there is no such project in the repo. Option A's "full rigor" would be rigor about a population of zero, which this project has already been burned by twice (frame-alignment rules, the "sequence" label, and the 5/5 false-positive `group` check that motivated ADR-0039 itself). Option B: ship the mechanism, state plainly in the ADR that (c)'s output is unmeasured, and make closing that fog conditional on a fixture that actually contains cross-element same-property motion.

**Trade-offs:**

- *R2-Q1:* Narrowing means a hand-edit that peels one of several coincident boundaries apart stays unreported until someone picks up the fog. The alternative — folding boundary-vs-boundary into this ticket "for output-shape consistency" — would attach a keyframe-instant design to a re-litigation of ADR-0032's already-shipped semantics, and consistency is achievable anyway by giving the sentence template a grouping-key slot (prior-round Q2) that a future boundary-pair check can reuse.
- *R2-Q2:* Including self-pairs costs one more instant-type in the predicate and a handful of output lines on real edits; the cost of exclusion is shipping a check whose only measurable case is deliberately turned off. The ADR-0036 precedent does not transfer — it excluded on *presence* grounds, and destruction inverts the information content.
- *R2-Q3:* Option B costs an honest "unmeasured" line that some reader will mistake for "unfinished." Option A costs the credibility of the ADR the first time a real lower-third project produces noise nobody predicted. Not designing (c) at all would require special-casing the predicate to *exclude* cross-element keyframe pairs, which is more code and a worse story than including them with a measurement caveat.
