🗳️ **Juror** (Fable) — **VOTE: Q1: exact coincidence only, first pass — but define "held" per *property-pair over the ref's history of one diff*, and leave fixed-offset as an explicitly named follow-up. Q2: reuse the grouped-deltas-as-facts convention, with one new sentence template per hazard — no new report shape. Q3: no severity; stay purely descriptive, matching slack. Q4: confirm — never-correct coupling stays explicitly out of scope; the prior ADRs did not miss a way to close it.**

**Reasoning:**

*Q1.* ADR-0039's four failures were all failures of *inferring intent from structure*. Fixed-offset detection re-introduces that inference: two keyframes 300ms apart in the ref and 300ms apart in the current file "held," but so did every pair of instants whose difference happened to be preserved — and in a 60-element file with 120 boundary endpoints, the number of preserved pairwise differences after any localized edit is enormous. You'd be reporting the *non-destruction* of relationships nobody authored. Exact coincidence is the one relationship a reader can verify by eye in the JSON (two identical numbers), which is Montagent's stated bar. The fixture data supports narrow scope: 92/120 endpoints already coincide with *something*, so even exact-coincidence destruction will fire on ordinary cuts; the design's real work is choosing the grouping key (same-track cut vs cross-track vs same-property keyframe), not widening the relation class. Fixed-offset should be named as deferred, not silently omitted, because ADR-0039's "staggered entrance" case *is* a fixed-offset relationship and someone will ask.

*Q2.* The existing convention already encodes exactly the shape needed: a population, a common delta, and the exceptions. "Destroyed coincidence" is literally "N records shared instant T in ref; K of them moved +Δ; M did not" — the `vo-quiz-answer did not` sentence. Coupled-motion-drift is the same sentence keyed on `(property, keyframe time)` instead of element boundary. Inventing a second report shape would force every agent consuming `compare` to parse two grammars for one idea. The only addition is the grouping key appearing in the sentence ("…keyframes on `scale` at 30603…"), which the current template doesn't carry.

*Q3.* Severity is `validate`'s judgment vocabulary, and ADR-0006/0061 fence it there deliberately. `compare` cannot know whether a destroyed coincidence was the edit's *purpose* (you intentionally split the bar from the text) or its *casualty*. Assigning `review` to every one would reproduce ADR-0039's 5/5 false-positive rate in a different tool. Slack already proves the descriptive-only stance works; breaking consistency here would mean `compare` has two finding classes with different epistemic status.

*Q4.* Confirmed. Without a declared coupling field, "correct" has no referent in the file — there is nothing for either tool to compare against. The only path the ADRs "missed" is a schema field, which the question already notes nobody has proposed; proposing it is a separate ADR with its own costs (every author must declare intent; undeclared = unprotected), not a mechanics detail for this ticket. The 7 self-coincidences in the fixture (keyframe at own start) are a hint that *some* couplings are cheap to declare implicitly, but that is a future schema conversation.

**Trade-offs:**

*Q1* costs missing staggered-offset drift (the lower-third whose text always trails its bar by 300ms). Accepting that loss now is cheaper than a false-positive storm that gets the whole check retracted as ADR-0039 was. *Q2* costs some sentence length as the grouping key is added, and the risk that agents assume all `compare` lines are boundary-shift lines; a key prefix mitigates. *Q3* costs the agent having to decide for itself whether a reported destruction matters — but that is precisely the fact/judgment boundary the project chose, and an agent reading "3 keyframes on `opacity` at 12000 in ref; 2 moved +400, `lt-text` did not" has everything it needs. *Q4* costs leaving a real hazard open, honestly labeled, rather than pretending a stateless tool can see intent.
