# Juror C1 verdict — issue #48, the `fit` vocabulary

Evidence base: issue #48; ADR-0013 (all), ADR-0012 (clip/aperture), ADR-0014 (gravity, text box), ADR-0006 (opt-in rule), ADR-0003 (asymmetry guard), CONTEXT.md; the 8 image elements of `fixtures/en-halloween-decorating/en-halloween-decorating.montaget.json`; `fit_rounding_scan.py` run clean (exit 0); PNG headers of all five image sources read directly (photos 1536x2720, logo 800x800).

## Q1

**Decision:** `fit` is a derivation claim — an assertion about how the author computed `width`/`height` — not a render instruction. At render time it does nothing: under ADR-0013's "declared rect is authoritative at render," the source is resampled to exactly the declared rect whatever `fit` says. Two files identical except for their `fit` value render identical pixels. Its actual consumers are (1) `validate`/`render`'s fit-deviation check, for which it is the required input — without the claim there is nothing to check the rect against — and (2) the next agent reading the file, for whom it records the rect's provenance (this is the stale-source defence: swap the source and the claim is what makes the now-wrong rect detectable at all).

**Why:** Work backwards from the settled render rule. The renderer's inputs are `x`,`y`,`origin`,`width`,`height`,`clip`,transform. There is no free variable left for `fit` to bind — the rect says where and how big, `clip` says through what. So `fit` cannot be a layout mode; the only thing it can be is a statement *about* the rect. That is exactly the role ADR-0013's fit-deviation note already consumes it in: "declared 1912; cover from images/06.png (1536x2200) is 1546." The check is meaningless without a declared rule to recompute.

**Strongest counter:** ADR-0007/0012's own maxim — "a field the renderer cannot honour is worse than no field" — argues for deleting `fit` outright rather than keeping a render-inert assertion, and a CSS-trained agent will read `fit:"cover"` as `object-fit: cover`, i.e. as an instruction, and be surprised that changing it changes nothing. The answer is that `fit` *is* honoured — by `validate` and by `render`'s identical checks — unlike `gravity`, which no tool consumes; but the misreading risk is real and the schema prose must say "checked, not rendered" in so many words.

## Q2

**Decision:** The box `bw x bh` is the `clip` rectangle's width and height. Determined from the fixture, not from prose: for `photo-06`, cover of 1536x2720 into clip 1080x1300 gives (width drives: 1080·2720 ≥ 1300·1536) slack `2720·1080 // 1536 = 1912` — exactly the declared 1080x1912, while cover into the frame (1080x1920) would give 1084x1920 and cover into the declared rect is circular. `handle-logo` is the instructive contrast: its declared rect (68x68) *equals* its clip, because 800x800 into 68x68 is an exact aspect match — so on that element alone box=clip, box=declared-rect and "no rounding needed" are indistinguishable. `photo-06`, whose declared height 1912 ≠ clip height 1300, is what separates the candidates and pins the box to `clip`.

When `clip` is absent, the declared rect itself is the box, and `fit` degenerates to an aspect-fidelity claim: the driving axis is chosen by the same integer cross-multiplication against the declared rect, and the claim checked is that the slack-axis value equals the floor rule from the driving axis — i.e. "this rect is the source's aspect, floored." That is precisely what an author fitting a source with no aperture computes, it needs no new rule (it is the same formula with box = declared rect, whose fixed point is the assertion), and it avoids the alternative of making `fit` require `clip`, which would force an aperture onto every full-bleed image that doesn't need one.

**Why:** Only `clip` reproduces both fixture geometries, and ADR-0012 wrote the derivation in prose ("a 1536x2720 source in a 1080x1300 box under fit:cover") — the box was always the aperture; ADR-0013 just never restated it.

**Strongest counter:** The absent-`clip` fallback quietly changes what `fit` means depending on a different optional field — the same word checks against two different boxes, which is a mild recurrence of the `box` two-meanings failure CONTEXT.md records. The defence is that it is one formula with one substitution, and the degenerate case is the formula's own fixed point, not a second rule; but a reader must still know which box a given element's claim is against.

## Q3

**Decision:** Required on every image (and future video) element. Omission is a schema error naming the closed value set, including the escape value — never a default and never a silent skip.

**Why:** ADR-0006's opt-in rule, as ADR-0014 applied it to the text box: "an omitted `height` is indistinguishable from a decision not to check." An omitted `fit` disables the stale-source check for exactly that element — the single check that catches the on-disk truth changing under a plausible-looking file — and does so invisibly, which spends `validate`'s one structural defence, uniformity. Defaulting instead fails ADR-0012's test both ways: default `cover` asserts a derivation the author may not have performed (a plausible camouflage), and default `stretch` *is* the decision-not-to-check made silent. A required field whose absence errors is the loud option, and once the vocabulary contains an explicit escape (Q4), requiring the field costs an author one honest word, never a lie. Cost to the corpus: zero — `fit` is already on 8 of 8 image elements.

**Strongest counter:** ADR-0012 defaults everything defaultable (`x`, `y`, `origin`, `scale`, `rotation`, `opacity`) and its "required, not defaulted" clause was argued for *size* specifically, because the source's dimensions are not in the document; `fit:"stretch"` boilerplate on every freehand image is real friction, and one could say a missing claim is simply no claim, like a missing `radius`. The reply is that ADR-0012's defaults are all values whose wrong default is loud or harmless; a missing check is the one class of omission ADR-0006 rules can never be silent.

## Q4

**Decision:** The closed v1 set is `cover`, `contain`, `stretch`.

- **`cover`** — inequality: fitted extent ≥ box on both axes (nothing of the box uncovered). Driving axis chosen by `bw*sh >= bh*sw`, takes the box dimension verbatim; slack axis `(s_slack * b_driving) // s_driving`, **floor**, exact integer arithmetic — verbatim ADR-0013, restated not re-decided. Floor preserves the bound because the exact slack is ≥ an integer `b`, so its floor is too.
- **`contain`** — inequality: fitted extent ≤ box on both axes (nothing of the source outside the box). Driving axis chosen by `bw*sh <= bh*sw`, takes the box dimension verbatim; slack axis floors, same single operation. Floor preserves ≤ trivially — it never rounds toward violating the bound even for a non-integral box, which is the strict sense in which floor is the uniquely safe direction here, and it keeps ADR-0013's tiebreak (2) promise: one rounding operation across the whole vocabulary. `contain` belongs in v1: ADR-0003 forbids "the fixture doesn't letterbox" as an argument against it, it is unremarkable in the CapCut/Premiere reference class, ADR-0013 already worked out its rounding as rationale, and admitting it now costs one clause where admitting it later is the `radius` argument re-run. What ADR-0013 refused was creating it *by implication*; this ticket is the explicit act.
- **`stretch`** — the escape: "do not fit this, use my rect." It names no inequality and derives nothing, so it has no rounding rule and suppresses the fit check entirely; it is the only value that is pure instruction-shaped, and it is honest, because rendering *always* resamples to the declared rect — `stretch` just declines to claim the rect came from anywhere.

Spent / misleading candidate names, per the ticket's demand: **`none`** is rejected — CSS `object-fit: none` means "render at natural source size," which in this format is the extent-derived-from-content that ADR-0012 bans outright; an agent reading `fit:"none"` through CSS would expect exactly the forbidden behaviour. **`fill`** is rejected — already spent in this format as the shape paint field (ADR-0014), and ADR-0005's killed "implicit `fill`" gives the word a third ghost; even though CSS `object-fit: fill` is semantically closest to the truth, the in-format collision is disqualifying under the one-word-one-concept rule. **`scale`** is spent (transform property); **`crop`** is a CONTEXT.md avoid-word for `clip`. `stretch` collides with nothing in the format and has no CSS `object-fit` value to contradict (CSS spells that concept `fill`).

**Why:** Each value ships with its inequality and rounding, per ADR-0013's normative demand; the escape is chosen by eliminating every collision the format has already recorded.

**Strongest counter:** Against `contain`: it is genuinely unevidenced — zero uses anywhere — and a closed vocabulary can grow later without a schema break, so v1 could ship `cover` + `stretch` and stay smaller. Against `stretch` as a name: an author whose freehand rect happens to be aspect-true writes `stretch` and the word overstates distortion; `exact` or `declared` would describe the claim ("this rect is authored") rather than the pixels. I hold `stretch` because the field's danger case — deliberate anisotropy over a re-exported source — is the one the name must read correctly on, and there it is exactly right.

## Q5

**Decision:** Retire it. `gravity` on an image becomes a schema error, message naming the replacement: the fitted rect's placement is `x`/`y`/`origin` against the `clip` aperture (ADR-0014 already made `gravity` on text/shape an error naming `origin`; this completes the retirement for the one type where it was still legal). Fixture cost, stated honestly: this is **not** a zero-byte change — 8 committed image elements each drop one field, `migrate.py` and `verify.py` must change (verify currently *asserts* `gravity` on images), and ADR-0014's zero-byte streak ends. That cost is accepted because the alternative is worse.

**Why:** The 8-of-8 inertness ADR-0013 measured is not a corpus accident — it is structural. Under declared-rect-authoritative, the renderer's inputs (`x`,`y`,`origin`,`width`,`height`,`clip`) leave no degree of freedom for `gravity` to bind on *any* file: which part of the source survives is fully determined by where the rect sits relative to the aperture, and the author already states that with `x`/`y`. So this is not "the fixture doesn't use it" (which ADR-0003 forbids as an argument); it is "the settled model gives it nothing to do, ever." A field the renderer cannot honour is the format's named failure class — the `opacity`-on-audio trap in image clothing: an agent writes `gravity:"bottom"` expecting the crop to change, and nothing changes, forever, plausibly. Keeping it as a checked assertion (validate that `x`/`y` are consistent with the declared gravity) was considered and rejected on ADR-0006's own `kind`-field argument: a second fact derivable from the first is a fact that drifts.

**Strongest counter:** ADR-0013 handed `gravity` a *measured fact, not a decision*, and 8 elements from one geometry are thin evidence; a future `fit`-driven authoring mode — where an agent asks `measure`/`query` to *derive* the rect from source+clip+gravity — would give the word a real job as the input to that derivation, and retiring it now means re-adding it later. The reply: that tool can take a gravity *argument* without the schema carrying a gravity *field*; what the document records is the derived rect, per the format's whole philosophy. But if declared-rect-authoritative is ever reopened (ADR-0013 flags that coupling on floor-vs-ceil too), `gravity` comes back to life, and this retirement would have to be reversed.

## Q6

**Decision:** Severity `error`, gated on the vocabulary this verdict creates. Predicate — ADR-0013's second recorded shape, adopted exactly: for an element declaring `cover` or `contain` whose source is probeable, compute the driving axis by integer cross-multiplication from `(source, box)`; the declared driving-axis value must equal the box dimension **exactly** (zero grace), and the declared slack-axis value must be a member of `{floor(exact), ceil(exact)}` computed in integer arithmetic (`floor = n//d`, `ceil = -((-n)//d)`; the set is a singleton when exact is integral). Outside the set: `error`, message naming both legal repairs — the rule value, or keep the rect and write `fit:"stretch"`. Inside the set but not equal to the rule value (i.e. a ceil-author's 1913): the existing ADR-0013 `note` stands, naming the rule value — determinism drift, not self-contradiction. `fit:"stretch"`: no check runs, by construction. Unprobeable source: `UNCHECKED`, per ADR-0013 — and note this becomes the format's first *media-dependent* error, so ADR-0013's "an unprobeable source can never suppress an error" property no longer holds universally; the mitigation is the one ADR-0013 itself states: `render` must decode the source to draw it, so at the chokepoint that actually ships video the check is always answerable.

The membership shape over the step-count shape for ADR-0013's own recorded reason: a step count is not scale-free — the same 2-step deviation is 0.105% on `photo-06`'s 1912 and 2.941% on `handle-logo`'s 68, a 28x spread in one file (reproduced by the scan) — while membership is exact at every scale and needs no threshold to tune.

**Why `error`:** a rect contradicting its own declared `fit` given the media on disk is the document contradicting itself — ADR-0006's charter, and the definition of `error` ("guaranteed wrong") applies at the claim level: whatever the pixels look like, the file's stated derivation is false. The 23.6% stale-source case renders today with only a note; it is the exact defect class ("the truth changed on disk, not in the project") ADR-0006 built the probe for. The only thing that blocked `error` was the absence of a legal way to decline the fit; `stretch` is that spelling, and it does not collide with the `scale` animation channel the way ADR-0013's interim escape did on 7 of 8 elements.

**Checked against the committed fixture, computed not guessed: the rule breaks 0 of 8 elements.** PNG headers read directly from disk: seven photos are 1536x2720 into clip-box 1080x1300 — width drives, declared 1080 = box 1080, exact slack 1912.5, membership set {1912, 1913}, declared 1912 is a member (it is also the rule value, so not even the note fires); `handle-logo` is 800x800 into 68x68 — exact, set {68}, declared 68 is a member. 8 PASS, 0 ERROR.

**Strongest counter:** An author with a deliberately re-composed source who *likes* the current crop is now render-blocked until they edit the file, and the "self-contradiction" framing proves too much — the pixels may be exactly what was wanted, so "guaranteed wrong" is true of the claim, not the video, and ADR-0006's severity table is worded about the render. Admitting ceil into the legal set also softens ADR-0013's determinism stance (two authors' rects both pass structure, distinguished only by a note). Both are accepted costs: the repair is one word (`stretch`), and erroring on 1913 would flunk a geometrically-covering rect over a rounding tiebreak ADR-0013 itself called non-geometric.

## Anything the questions missed

1. **`fit` on `type:"video"` is undecided by every document, and this verdict's rules should be written type-generic ("sourced visual element") now.** ADR-0003 makes video elements obligatory; a fit vocabulary specced only for images repeats the ellipsis this ticket exists to close. The probe already reads video dimensions for other checks.
2. **The absent-`clip` box fallback (Q2) needs one worked example in the ADR**, because it is the one place the same field checks against two different boxes — the exact ambiguity class (`box`'s two meanings) this format has been burned by. One `photo` element with and without `clip`, numbers shown, closes it.
3. **The UNCHECKED interaction deserves a sentence of its own in the ADR:** this becomes the first error-severity check that requires media, quietly weakening ADR-0013's stated structural property that no unprobeable source can suppress an error. It is sound only because `render` re-runs the checks with the source necessarily decodable; if a future `render --pre-flight` or remote-URL path ever renders without a probe-equivalent, this error silently degrades to validate-only.
4. **Retiring `gravity` (Q5) while adding `stretch` (Q4) should land as one migration**, since both touch the same 8 elements' schema surface and `verify.py` assertions; two sequential migrations of the only real project file doubles the chance one of them is the stale half.
