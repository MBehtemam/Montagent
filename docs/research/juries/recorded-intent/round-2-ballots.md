# Round 2 — ballots, verbatim

Question: [`round-2-question.md`](round-2-question.md). Three jurors, dispatched
in parallel, no juror seeing another's ballot. Q1–Q4 were shown with the
provisional answers adopted after round 1 and explicitly opened to being
overturned; Q5–Q8 were new.

Outcome: twenty-three confirmations, one overturn (Juror 3, Q3, symmetric
clause only). See the [README](README.md) for the anchoring caution that
qualifies the margin.

🗳️ **Juror 1** (Claude Opus 5) — **Q1 VOTE: CONFIRM (b)**

**Reasoning:** The gap is singular — the format records values but not the author's reason for them — and the fix rule is singular: a renderer-ignored declaration whose only consumer is `validate`, which re-derives and compares. That is exactly `fit`, already proven in the codebase. But the *content* of the claim differs per axis in kind, not degree: a time derivation is arithmetic on one document's integers; an audio partner link is an identity with no arithmetic at all (Q3 concedes it cannot even be violated); a motion coupling has no measured shape yet. One generic field (a) would have to carry a rule vocabulary wide enough to span "subtract 300ms" and "this text was calibrated against that audio source" — and a vocabulary that general *is* an arithmetic language with an escape hatch, which is the disease. Four unrelated gaps (c) would let each axis re-decide severity, repair class, and placement, and the four would diverge into four dialects of the same idea.

**Trade-offs:** (b) costs schema surface — several named fields where one would do — and a discipline that each future field must be argued against the pattern rather than assumed into it. That discipline is the point: the shared constraint is what stops the fourth field from being an expression language. The real risk is that (b) is (c) wearing a uniform if the shared rule is never written down as binding; the ADR must state the pattern's obligations (renderer-ignored, `validate`-only, closed rule set, one argument max) as conditions of admission, not as description.

🗳️ **Juror 1** (Claude Opus 5) — **Q2 VOTE: CONFIRM**

**Reasoning:** ADR-0036's three reasons were all about the *renderer*: read-by-reading breaks because the rendered geometry is not on the page; the reference degrades to a stale literal on the first shift; the element's geometry gains a silent second author. An inert, renderer-ignored id reference triggers none of them. The rendered value stays the literal that is written down — reading the file still tells you what is on screen at 6s. There is nothing to go stale because nothing is resolved at render. There is no second author because the reference authors nothing. What it does is the opposite: it names, in the file, a relationship that currently exists only in the author's head. The earned-per-axis condition is the load-bearing half of this answer — ADR-0012 removed the last element-to-element reference for a reason, and the only thing that justifies paying that invariant back is measured proof that inference fails, which audio has (11-of-22 provably ambiguous) and motion does not. On the dangling case: `review` is defined as "look at a frame and you will know." No frame renders differently for a dangling id, and no frame names the intended element. So `review` is definitionally wrong, and the repair is genuinely undetermined — a typo'd id could have meant any of several sources. `error` + refuse-class is the only pairing consistent with the vocabulary.

**Trade-offs:** The cost is that "zero element-to-element references" stops being a slogan and becomes "zero *live* references," a weaker and more easily eroded line. Future proposals will cite this precedent. Mitigation is structural, not rhetorical: the permission is per-axis, spent by an ADR carrying a measurement, and every grant must restate that the renderer never reads it. One genuine loss: a dangling id makes a document that renders perfectly fail `validate`, so `validate` failure now covers "the file's story is broken" as well as "the render is broken" — but that is already true of `fit`, and it is the price of provenance being checkable at all.

🗳️ **Juror 1** (Claude Opus 5) — **Q3 VOTE: CONFIRM**

**Reasoning:** The three-way split falls directly out of the finding vocabulary's own definitions rather than being imposed on it. Directional: the document says which value is source and which is derived and by what rule, so there is exactly one legal integer — identical to `fit`, so `error` + advise-class, and the advice is just the re-derived number. Symmetric: "these two stay equal" with no named source means a break leaves two candidate repairs (move A to B, or B to A) and the document contains nothing that chooses. Advise-class is defined as "fully determined by the document, the media and published semantics" — it is not determined here, so refuse-class `"none"` is mandatory, and the severity question then resolves to `review` because the document is legal and renders, and looking at the frame genuinely can tell you which side moved wrongly. That is the textbook `review` case. Partner-only: there is no arithmetic, so no re-derivation, so no violation is even expressible — the only checkable fact is existence, which Q2 already classes. Nothing is smuggled in.

**Trade-offs:** The awkwardness is that a symmetric declaration is a weaker tool than it looks — it downgrades to advisory, and an agent scanning for `error` will skip it. A tempting shortcut would be to require every declaration be directional so everything is `error`; I would resist that, because forcing an author to nominate a source for a genuinely mutual constraint invents intent the author did not have, and inventing intent is the exact failure this whole mechanism exists to avoid. The other cost: three finding shapes for one pattern is more surface to document. Worth it — collapsing them would mean either issuing advice the document cannot justify, or demoting the directional case below `fit`'s severity for no reason.

🗳️ **Juror 1** (Claude Opus 5) — **Q4 VOTE: CONFIRM**

**Reasoning:** Shipping the pattern plus exactly one field is right, and time-derivation is the right first field, but not primarily for the reason the provisional answer leads with. The decisive property is that time-derivation exercises the pattern's *full* machinery — directional claim, arithmetic re-derivation, `error` + advise-class repair, an integer argument, per-value placement — while spending none of the pattern's contested permissions. It is the complete proof of the mechanism at minimum architectural cost. Audio, by contrast, exercises almost none of the machinery: Q3 establishes it has no arithmetic and cannot be violated, so shipping it first would validate the pattern's weakest instance while simultaneously spending the Q2 id permission and reversing ADR-0012 — the worst possible ordering of risk against evidence. That audio is better-measured is true and irrelevant to this ordering, because measurement answers "does the gap exist," not "does the pattern work."

**Trade-offs:** The provisional answer's honesty requirement is essential and I would strengthen it: the ADR must state that the better-measured axis is being held back, that the reason is architectural (a separate ADR must pay ADR-0012's invariant), and that this is not a judgment that the audio gap is smaller. Without that sentence the record reads as if 4-of-52 outweighed 11-of-22, which would be false and would corrupt the evidence bar for every later axis. Cost: the karaoke gap stays open a cycle longer, and the 4-of-52 fixture is thin enough that a hostile reader can call the first field speculative — the census is the answer to that, and the ADR should cite it. Motion should not graduate on any timeline until it has a census; it currently has no evidence of any kind, and a ticket is the right place for it to earn one.

🗳️ **Juror 1** (Claude Opus 5) — **Q5 VOTE: optional, absence means no claim — CONFIRM**

**Reasoning:** `fit`'s argument does transplant verbatim, and the provisional answer is right to concede that rather than paper over it: an absent declaration and a deliberately-unrelated literal are genuinely indistinguishable, and that is a real, permanent hole. But `fit` was decided under a condition that does not hold here — it was *free*, because every element already carried the field, so "required" cost nothing and bought completeness. Here required costs 48 declarations of noise to check 4, on a format whose authors copy the nearest example. That last clause is the whole argument and it is stronger than a tax calculation: a required field with an escape value on a copy-propagating author population does not produce 52 considered decisions, it produces 48 copies of whatever escape value appeared in the first example. The field would then be *worse* than absent — it would look like 52 deliberate no-rule assertions while being 48 accidents, and `validate` would be certifying noise. Requiredness buys completeness only where the author population actually deliberates per field; here it buys a false completeness signal.

**Trade-offs:** The accepted cost is exactly as stated: the mechanism is structurally blind to undeclared relationships, so it catches breaks only in relationships someone bothered to declare, and a relationship an author forgot to declare is exactly the one most likely to break. The ADR must state that limit plainly as a property of the design, not bury it. Partial mitigations exist and should be named but not adopted now — a `note`-class census surfacing undeclared arithmetic coincidences is precisely what ADR-0063's population-explosion argument warns against, and `UNCHECKED` is the right long-term home for "this document declares nothing" if it ever becomes worth saying. Optional is also the reversible choice: optional can be tightened to required later once real declaration density is known; required cannot be loosened without stranding every file that already carries the escape value.

🗳️ **Juror 1** (Claude Opus 5) — **Q6 VOTE: yes, closed enum plus at most one integer argument — CONFIRM**

**Reasoning:** Without the argument the mechanism does not cover its own founding evidence — the entire measured case is `end - 300`, and a pure enum expresses zero of the four fixture instances. A field that cannot express the finding that motivated it should not ship. The counter-argument deserves a real answer rather than dismissal: yes, a named rule with a free numeric argument is *one generalisation* away from an arithmetic language. But "one generalisation away" is the normal condition of every bounded design; what matters is whether the boundary is stateable and mechanically checkable, and this one is. The decisive test is the standing principle itself: can a reader know what is on screen at 6s by reading? Yes — trivially, because the literal is still written down and the renderer never reads the declaration. `{rule: "before-end", ms: 300}` adds no evaluation to the render path at all; it is a checkable assertion *about* a literal that is already there. `fit`'s `cover` is the exact precedent: a named rule taking an input, re-derived by `validate`, and nobody called it an expression.

**Trade-offs:** The three guards are not decoration, they are the whole line, and each must be enforced by `validate` and the schema, not merely stated in prose: the rule set is finite and published (so a new rule is an ADR, not a value); exactly one argument (so no rule takes two operands, which is where arithmetic begins); no composition (so no rule's argument is another rule, which is where a language begins). I would add one enforcement note: the argument's type should be fixed per rule by the schema — an integer millisecond count for time rules — so that "one argument" cannot later be widened to "one argument of any type," which is an escape hatch by another name. The residual risk is rule-set sprawl: five rules today, forty in two years, each individually reasonable. The mitigation is the same discipline Q1 asks for — admission to the rule set is an ADR carrying a census, not a convenience.

🗳️ **Juror 1** (Claude Opus 5) — **Q7 VOTE: beside the annotated value — CONFIRM**

**Reasoning:** The provisional reasoning is correct and its form is worth naming, because it is the same move that settles Q2: an element-level declaration would need a field naming *which* timestamp it describes, and that field is an intra-element pointer — a reference by another name, adopted specifically to avoid a reference. Trading an honest inter-element id for a disguised intra-element one is strictly worse, since the disguised one gets no ADR, no earned permission, and no dangling-id finding class. Beside the value, the subject of the claim is its location; there is nothing to point at and nothing to go stale when a keyframe list is reordered or spliced. It also keeps the claim where a reader's eye already is when they read the literal, which is the whole point of a provenance field — the claim and the value it explains should not be separated by a scroll. Placement also makes Q5's optionality cheap: an absent declaration is simply a bare value, with no per-element container to reason about.

**Trade-offs:** The cost is schema breadth — every site that can carry an annotatable timestamp needs the field defined at that site, which is more schema work than one field on the element and which must be done consistently or the pattern develops holes. It also means a future author wanting to state one claim over several of an element's timestamps has no place to put it; I regard that as correct rather than regrettable, since such a claim is a composition and Q6 has just ruled composition out. ADR-0041 is unaffected either way — canonical order follows schema order from wherever the field is declared — so key order is not an argument for or against, and the ADR should say so rather than leave a reader wondering whether placement disturbed it.

🗳️ **Juror 1** (Claude Opus 5) — **Q8 VOTE: `validate` alone; ADR-0063 narrowed, not reversed — CONFIRM**

**Reasoning:** Both sides of a declared derivation sit in one document, so the check is stateless and belongs to the tool defined as stateless-over-one-document. `compare` is defined by having an input `validate` lacks — the earlier state — and a declared relationship needs no earlier state: a break is visible in the after-document alone, which is precisely the property that makes this mechanism work on born-broken files, the case `compare` structurally cannot reach. Giving `compare` the check would duplicate `validate`'s logic for no new input, which is the same discriminator ADR-0037 used to kill the `derive` helper. Narrowing rather than reversing ADR-0063 is also exactly right and should be stated carefully: ADR-0063's reasoning was that an offset *inferred from arithmetic* is a hypothesis and the candidate population explodes. A declared offset is neither inferred nor unbounded, so that reasoning does not reach it — but the reasoning remains completely intact for undeclared pairs, which is still every pair in every existing file. Reversal would imply `compare` may now infer offsets, which is false and would reopen the explosion.

**Trade-offs:** The honest cost of `validate`-alone is a case it cannot see: a shift that moves both the source and the derived value together preserves the declared relation, so `validate` stays silent even if the coupling was meant to break — the declaration asserts the relation holds, not that it should have changed. Detecting that needs a before/after and is genuinely `compare`'s shape. I would not build it now — there is no evidence it occurs, and speculating a `compare` feature into existence is how ADR-0063's population problem returns by the back door — but the ADR should record it as the known boundary so a future ticket has a stated starting point rather than a rediscovery. One drafting caution: the narrowing must be written as "declared offsets are out of ADR-0063's scope because they are not inferred," not as "fixed-offset drift is now acceptable" — the second sentence undoes the ADR.

**Reasoning:** The four exemplars share a structural skeleton (renderer-ignored, validate-only, closed-vocabulary claim about how a value came to be) but differ in what varies within each: arithmetic offsets, symmetric equalities, and pure partnership have genuinely different failure and repair semantics. 🗳️ **Juror 2** (Claude Sonnet 5) — **Q2 VOTE: CONFIRM**

**Reasoning:** ADR-0036 rejected a reference the *renderer* consumes and that decays into a silent second author of rendered geometry on shift. A declaration only `validate` reads never touches rendered output and never goes stale in a way that misleads a renderer — it just becomes a finding. That is a different object, not a reopening. 🗳️ **Juror 2** (Claude Sonnet 5) — **Q3 VOTE: CONFIRM**

**Reasoning:** The severity classes are already defined by what the reader must do. A directional declaration has exactly one correct value re-derivable from the document — that's the `fit` case exactly, so `error`+advise follows without new reasoning. A symmetric declaration names no source, so there is no principled way to pick which side is "wrong" — a human must look at a frame to judge which was intended, matching `review`'s definition precisely, and no computed integer exists to advise. **Reasoning:** The `fit` transplant argument ("omitted is indistinguishable from undecided") is real but `fit`'s required-ness was earned by being free. Here it's a 13x tax on a format whose authors are agents pattern-matching off the nearest example — that tax will produce copy-pasted, meaningless declarations on the 48 unrelated timestamps, which is worse than silence: it manufactures false confidence that "we checked" when the declaration was never a real claim. 🗳️ **Juror 2** (Claude Sonnet 5) — **Q6 VOTE: agree, closed rule set + at most one integer argument**

**Reasoning:** The bright line holds: finite published rule names, exactly one argument, no composition. This is structurally identical to `fit`'s `cover` taking an implicit aperture input — a parameter is data consumed by a fixed, named rule, not a program. The rejected option (a) was an *open* arithmetic language where R itself is unbounded; `{rule, ms}` is one closed rule with one scalar slot, which is a categorically smaller, enumerable surface.
**Trade-offs:** This is genuinely "one generalization away" from the rejected option, as the dissent notes — the discipline has to be enforced by never letting a second rule accept a second parameter or letting two rules chain. That enforcement is a standing tax on every future rule proposal, but it's a bright line that's checkable at review time, unlike "no evaluation" in the abstract.

🗳️ **Juror 2** (Claude Sonnet 5) — **Q7 VOTE: CONFIRM**

**Reasoning:** All four fixture cases point at one specific timestamp, not at the element as a whole; an element can carry multiple timestamps (start, end, keyframes), so an element-level declaration would need its own pointer field to say which value it describes — trading an inter-element reference for an intra-element one, which is not a win, just a relocation of the same problem. Placing the declaration beside the value it annotates needs no pointer at all; ADR-0041's schema-order key placement falls out for free.
**Trade-offs:** Beside-the-value placement means a declaration can't easily express "this whole element is derived" as one statement — every derived value needs its own annotation even if several move together for the same reason. That's a minor verbosity cost, not a structural one.

🗳️ **Juror 2** (Claude Sonnet 5) — **Q8 VOTE: CONFIRM**

**Reasoning:** ADR-0063's refusal was about an *inferred* hypothesis exploding combinatorially across every pair of unmoved instants in a 60-element file. A declared relationship is not inferred — its population is exactly the set of declarations an author wrote, which is small and explicit, so the explosion argument doesn't apply. But that doesn't mean `compare` needs to gain a feature: both values already sit in one document, so `validate` can check the relationship statelessly without needing a before/after pair at all. There is nothing left for `compare` to add.
**Trade-offs:** Recording this as "narrowed" rather than "reversed" costs a small amount of documentation precision now, but it accurately preserves ADR-0063's reasoning as still valid for the inferred case, which future axes may need to invoke again.

🗳️ **Juror 3** (Claude Fable 5.1) — **Q1 VOTE: CONFIRM (b)**

**Reasoning:** The gap is one gap (provenance, per ADR-0037's re-diagnosis) and the fix is one rule (a renderer-ignored claim that `validate` re-derives, structurally `fit`). That argues for a shared pattern. But (a)'s "R ranges over arithmetic" is the expression language wearing a field name: the moment R is an open set, an agent reading the file has to evaluate R to know whether the value is right, and the closed-schema principle loses its anchor. Per-axis named fields with closed vocabularies keep every legal rule enumerable and published, and let each axis carry its own severity table (Q3) and its own id-permission status (Q2), which a single generic field could not do without a discriminator inside it. Q5-Q8 reinforce this rather than undermine it: the "at most one integer" line in Q6 is only defensible if the enum it attaches to is small and axis-specific.

**Trade-offs:** (b) costs a new ADR-sized decision every time an axis graduates, and the vocabularies may drift stylistically. (c) is cheaper per ticket but forfeits the constraint that all four are the same shape, which is exactly what stops the fourth exemplar from being solved with a live reference. (a) is the cheapest to write once and the most expensive forever.

🗳️ **Juror 3** (Claude Fable 5.1) — **Q2 VOTE: CONFIRM**

**Reasoning:** ADR-0036's three objections were: the renderer reads it, it degrades to a stale literal on the first shift, and it gives geometry a second author. A recorded, `validate`-only reference fails all three tests for the objection to apply: no renderer reads it; it does not degrade on shift, it *detects* the shift (that is its whole job); and the literal remains the sole author of what renders. It is a different object. The per-axis, earned framing is right because the format's zero-references invariant (ADR-0012) is a real asset and should be spent only where inference is measured to fail (11-of-22 for audio meets that bar; nothing else does yet). On the dangling id: `error` with refuse-class repair is correct, but the stronger reason is referential integrity, not the frame test. A closed schema that admits a reference type must require the reference to resolve; an unresolvable reference is a malformed document, the same class as a keyframe that names a nonexistent property. The frame argument is a supporting reason, not the load-bearing one.

**Trade-offs:** Admitting any id reference means `shift`, `fmt` and any future rename tool now have a second place to keep coherent. The alternative, `review` for a dangling id, would let a document with a broken declaration pass as "legal, renders," which is true of the pixels and false of the document.

🗳️ **Juror 3** (Claude Fable 5.1) — **Q3 VOTE: OVERTURN (symmetric clause only)**

**Reasoning:** Directional: `error` + advise-class, confirmed, identical logic to `fit`. Partner-only: cannot be violated, confirmed; its only finding is the dangling id from Q2. Symmetric: the provisional answer is wrong and, worse, contradicts Q2's own reasoning. `review` is defined as "legal, renders, and you must look at a frame to know if it was meant." A violated symmetric declaration has already told you it was not meant; the document itself asserts the inconsistency. No frame can add information, exactly as Q2 argues for the dangling id. The finding vocabulary already has the right slot for "guaranteed wrong, fix depends on intent": **`error` + refuse-class `"none"`**. Using `review` here would make the severity depend on whether the arithmetic happens to have one root or two, which is not what the classes are named for.

**Trade-offs:** `error` + refuse means a symmetric break blocks render with no tool able to fix it; that is the intended guarantee of refuse-class, not a cost. The provisional `review` was softer and easier to live with in a file with many symmetric claims, but softness here is precisely the "indistinguishable from an edit that never had it" disease the ticket is about.

🗳️ **Juror 3** (Claude Fable 5.1) — **Q4 VOTE: CONFIRM**

**Reasoning:** Time-derivation is directional (so advise-class, the cleanest severity), needs no id, and has 4-of-52 measured. It is the only axis where the pattern can be shipped without touching the zero-references invariant, so it is the right first instantiation of the pattern ADR. Audio is better-measured but its entire finding set after Q3 is "partner missing," i.e. a referential-integrity check; the checking value it adds is small relative to reversing ADR-0012, which deserves its own record with its own vote. **Trade-offs:** The ADR must say in plain words that audio is held back on architectural grounds, not evidential, or the next reader will conclude 11-of-22 was judged insufficient. Holding audio also means the karaoke ambiguity stays unflagged for one more cycle.

🗳️ **Juror 3** (Claude Fable 5.1) — **Q5 VOTE: CONFIRM (optional, absence = no claim)**

**Reasoning:** The `fit` argument transplants; the `fit` economics do not. Required-with-escape would put `literal` on 48 timestamps so that 4 can be checked, and agents copying the nearest example will propagate `literal` rather than think, which makes the required field a decision-not-to-check with extra bytes. 🗳️ **Juror 3** (Claude Fable 5.1) — **Q6 VOTE: CONFIRM**

**Reasoning:** Without the integer, the field checks zero of the four measured exemplars, so the evidence forces it. An integer argument is data: reading `{rule: "before-end", ms: 300}` requires no evaluation beyond what reading `8000` next to `end: 8300` already requires. The bright line holds if all four parts are stated: finite published rule set, exactly one argument, the argument is a non-negative integer in the value's own unit with direction carried by the rule name (no signed arithmetic), and rules do not compose. `fit`'s `cover` taking the aperture as an implicit input is the honest precedent.

**Trade-offs:** This is one step from option (a) and the ADR must say so and name the step it refuses: a second argument, a signed argument, or a rule that references another rule. Any of those is a new ADR, not an extension.

🗳️ **Juror 3** (Claude Fable 5.1) — **Q7 VOTE: CONFIRM (beside the annotated value)**

**Reasoning:** All four fixture cases annotate one specific instant. An element-level declaration would need a selector for which timestamp it describes, and that selector is an intra-element pointer, which reintroduces exactly the reference the pattern is trying not to need. Sibling placement binds the claim to the value by adjacency and by naming (the field name must encode which sibling key it annotates, e.g. a `start`-annotating key distinct from an `end`-annotating key), so keyframe records carry their own and ADR-0041 gives key order for free.

**Trade-offs:** The schema grows one optional key per annotatable timestamp field rather than one per element, and the JSON for a declared value is visually heavier. That weight is the point: the claim sits where a reader's eye is when reading the number.

🗳️ **Juror 3** (Claude Fable 5.1) — **Q8 VOTE: CONFIRM**

**Reasoning:** A declared relationship is fully checkable on one document with no I/O, which is `validate`'s exact remit. `compare` would only re-run the same check on the after document, and anything it could add (the declaration was deleted between before and after) is already a plain field diff. ADR-0063's refusal rested on inference plus population explosion; a declaration removes both, so the reason for the refusal stops applying to declared offsets while remaining fully correct for inferred ones. That is a narrowing, and it should be recorded that way so no reader thinks `compare` now hunts for preserved offsets.

**Trade-offs:** Confining the consumer to `validate` means a shift that breaks a declared offset is caught only when someone runs `validate`, not in `shift`'s own output. If `shift` later wants to warn inline, that is a `shift` ticket, and it should reuse `validate`'s check rather than grow its own.
