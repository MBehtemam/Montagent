🗳️ **Juror 2** (Sonnet 5) — **VOTE: Q1: `--from`/`--to`, same half-open `[from,to)`, same defaulting (omitting `--to` is an error) — no `--per-state`/`--each-cut` spelling. Q2: (a), presence of `--from`/`--to` is the mode, `--at` + `--from` refused as malformed. Q3: both surfaces. Q4: refuse `--full` with a range as an invocation error naming why. Q5: `--png` carries over unchanged; the plain-text form must carry a one-sentence prose disclosure unconditionally, with full structured detail behind `--json` — this is already settled by ADR-0094 §6, not open here. Q6: this ticket says nothing about `--crop` beyond refusing `--crop` + range for now as not-yet-legal; ownership stays with #406. Q7: (a), the per-tile label discharges the caption obligation, and ADR-0011 is amended accordingly.**

**Reasoning:**
- Q1: Consistency is the only thing worth paying for here — `query`/`preview`/`render` already trained the agent's fingers on `--from`/`--to`, half-open, no silent "to the end." Inventing `--per-state`/`--each-cut` would treat the trial agents' vocabulary as a spec when it was really them reaching for "a range" without knowing the verb had one yet; ADR-0094 already settled that the collapse to visual states happens automatically inside `frame`, not via a flag that names the collapse.
- Q2: `measure`'s precedent is exactly this shape — mutually exclusive argument groups refused in the verb, not `clap`. `--at` and a range answer two different questions ("one instant" vs "a span"); letting both compile invites a caller to have to guess which one wins.
- Q3: The trial agent's CLI-looping story is an argument *for* the sheet fixing the round-trip cost, not for cutting a surface. MCP wants the image inline because the agent's loop lives there; CLI wants a file because a terminal can't render pixels, and it already has `--out`. Nothing about the range invalidates either need.
- Q4: ADR-0095 already removed the thing `--full` used to buy (true-pixel rasterization is now what *always* happens before compositing down), and it already ruled out per-call knobs ("no flag for 'give me 40 tiles'"). A flag that used to mean something and now means nothing should say so loudly, not degrade to a no-op a caller won't notice went silent.
- Q5: `--png` is untouched by anything measured — #397 showed encoding is token-flat, so nothing about ranges changes that math. `--json` is a smaller question than framed: ADR-0094 point 6 already mandates the unconditional prose sentence restating the disclosure, so this ticket has nothing left to decide except to not contradict it.
- Q6: #406 is named explicitly as owning this, and it's blocked on a live bug (#402). The only thing worth stating now is a placeholder refusal so the combination doesn't quietly half-work before #406 lands — anything more is scope creep into a ticket this court was told isn't ours.
- Q7: The caption's entire job (per ADR-0011) is stopping mis-attribution of a defect to the wrong element. At sheet scale, 18 full stacks cost 20.1x for information the per-tile label plus the mandatory disclosure fields (provenance, skipped, blind_to) already carry in cheaper form. A single cut-list block (b) restores per-range info but loses the per-tile attribution that's the actual defense against the wrong-photo-style defect landing on the wrong tile.

**Trade-offs:**
- Q1: costs nothing but restraint — the trial agents' preferred spelling doesn't survive contact with the verb table's own consistency argument.
- Q2 vs (b): a `--sheet` flag would be more discoverable to a human skimming `--help`, but it creates a second way to say "range" alongside `--from`/`--to`, which is exactly the redundancy `measure`'s mutual-exclusion precedent exists to avoid.
- Q3 vs MCP-only or CLI-only: dropping either surface pushes work back onto the caller that this feature exists to remove — MCP-only forces the CLI back to N-loop `render`-style calls it already had before this ticket; CLI-only strands the agent that never leaves MCP.
- Q4 vs silently ignoring or giving new meaning: silent ignore is the worst option on the table — a flag that "does nothing now" reads as broken rather than resolved, and a new meaning invents a knob ADR-0095 explicitly said this feature must not have.
- Q5: putting the full structured disclosure only behind `--json` (the more permissive reading of the question) would save output size in the common path, but ADR-0094's "plus one sentence of prose" line was written to prevent exactly that — a caller who never passes `--json` must still get the rule/skipped/blind_to gist, or the defence the whole ticket rests on (disclosure catches what selection rules miss) silently doesn't apply to CLI's default output.
- Q6: saying nothing at all (not even the not-yet-legal guard) risks the combination "working" by accident (e.g., cropping the first tile only) before #406 defines it; over-specifying now (locking in "existing `--crop` composed with existing range") pre-empts #406's actual open question, which is whether cropping should exist here at all given the wrong-photo defect vanishing on a cropped sheet.
- Q7 vs (c) all 18 blocks: paying the 20.1x buys nothing not already in the label/disclosure, and it's the literal case ADR-0095 said correctness-cliffs at >20 image blocks per request; this doesn't add image blocks, but the analogous cost bloat is a text-budget version of the same failure mode. (d) "something else" was considered and rejected as a non-answer — the evidence points cleanly at (a).
